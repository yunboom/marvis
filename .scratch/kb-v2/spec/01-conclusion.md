# 1 结论

知识库按「Postgres 存页面和修订、改动先进草稿、草稿提交为变更请求、合并时做三方合并」重做，不用 git，也不绑定外部仓库；对外只提供导出 OKF bundle。人只读、批注、审核；所有页面改动由智能体用飞书 CLI 式的 `fetch` / `patch` 命令写进草稿。一期知识库代码整体废弃；聊天、智能体构建器、任务令牌、自动化、WebSocket 原样复用，不为知识库做定制改动。

|  | 做法 | 
| 内容 | 页面按主题嵌套，正文拆成带稳定 id 的块；主线是 `kb_page`，历史是只追加的 `kb_page_revision`（决策 57） | 
| 页面格式 | OKF v0.2 页头 + 论断（Claims）+ 脚注引用；首页 quickstart；页面按领域分区；默认 Schema 全文见第 4 章（决策 55、58、63、67） | 
| 人 | 阅读、批注、审核、合并；不能在界面上编辑页面 | 
| 智能体 | 在「知识库作业」的对话里按块读写页面，改动进这个作业的草稿；用户确认后提交为变更请求 | 
| 合并 | 页面没被别人动过直接前进；动过则按块三方合并，同一块两边都改才算冲突 | 
| 创建 / 配置知识库 | 隐藏构建器智能体，左对话右配置，上下文带 OKF 摘要和 PURPOSE / SCHEMA 写法（决策 56） | 
| 其他智能体 | 执行任务、聊天、自动化时，说明里列出工作区的知识库（名称和简介）和读写命令（第 8.2 节） | 
| 导出 | OKF bundle（zip），链接改成相对路径，Obsidian 可直接打开 |
