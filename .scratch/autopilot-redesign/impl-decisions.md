# 自动化改版实现决策

实现过程中方案和设计稿没写清、由实现方按最佳实践自行决定的点。每条写清：问题、选择、理由、工单号。


1. **列表卡片保留虚拟化**（工单 01）
   - 问题：卡片网格是否还要虚拟化，列数怎么定。
   - 选择：按「行」虚拟化，一行 2 张、窄时 1 张；列数取滚动容器宽度（`ResizeObserver`），≥ 672px（与骨架用的 `@2xl` 同一阈值）两列。卡片定高 128px，行距 12px，作为虚拟化的定高契约。
   - 理由：工单要求长列表仍虚拟化；自动化数量通常不多，但按行虚拟化成本低，定高后与原表格同一套写法。
2. **卡片元信息行的取舍**（工单 01）
   - 问题：卡片没有表头，原表格各列如何在一行里表达，空值怎么显示。
   - 选择：顺序为 执行者 · 触发器 · 上次运行 · 下次运行 · 模式 · 创建者 · 创建时间，受「显示字段」开关控制；无触发器、无下次运行时整项省略；没运行过显示「未运行」；下次运行加「下次」前缀、创建时间加「创建于」前缀（裸日期分不清含义）；整行不换行、超出裁掉，保证卡片定高。
   - 理由：照设计稿 1.1 的元信息写法，空值省略比「—」更干净；前缀是去掉表头后唯一的语义来源。
3. **排序与显示保留现有弹层**（工单 01）
   - 问题：设计稿 1.2 画成单一菜单（勾选样式），现有实现是弹层（排序下拉 + 方向按钮 + 开关）。
   - 选择：保留现有弹层与交互，只把「列」改名「显示字段」；列头点击排序随表格去掉，排序只在该弹层里。
   - 理由：只改外观不改行为；弹层已满足「排序字段 + 升降序 + 字段开关」，换成菜单属于交互改写，收益小。
4. **指令摘要的纯文本化**（工单 01）
   - 问题：`autopilot.description` 是 markdown，卡片要两行纯文本。
   - 选择：纯函数 `instructionsPreview` 去掉标题、列表、任务勾选、引用、强调、删除线、代码、链接、图片、HTML 标签和提及语法，空白压成单个空格；两行截断交给 CSS `line-clamp-2`；指令为空时留空占位以保持定高。
   - 理由：不引入 markdown 解析依赖；列表页每张卡只需近似纯文本，正则足够，矩阵测试覆盖各语法。
5. **删除确认只剩单个**（工单 01）
   - 问题：去掉批量后 `DeleteAutopilotsDialog` 的复数文案（`description_one/_other`）还要不要。
   - 选择：改名 `DeleteAutopilotDialog`，只接受一行；文案合并为带名称的 `description`。zh / ja / ko 原来只有 `_other`（不显示名称），现在六种语言都显示名称。
   - 理由：决策 6 去掉批量，复数分支已无调用方。
6. **卡片的可访问性与中键**（工单 01）
   - 问题：卡片用什么语义，「…」是否会误触发卡片导航。
   - 选择：列表 `role="list"`、卡片 `role="listitem"`，名称取标题；导航仍是 div + `useRowLink`（与原表格行一致）。「…」外层改用 `rowLinkInteractiveProps`，同时拦截 click 和中键 auxclick（原来只拦 click，中键点「…」会新开标签页）。
   - 理由：保持原导航行为，顺带修掉中键穿透。
7. **模板抽成独立模块**（工单 01）
   - 选择：`TEMPLATES` 移到 `autopilot-templates.ts`（`AUTOPILOT_TEMPLATES`），新建下拉和空状态共用。
   - 理由：两处入口同源，页面文件减负。
8. **顶栏不用 BreadcrumbHeader**（工单 02）
   - 问题：仓库其它详情页多用面包屑顶栏，设计稿 2.1 是「返回 + 两行标题」。
   - 选择：照设计稿，与知识库作业页同款：返回图标按钮（`router.push` 回自动化列表）+ 标题 / 「自动化」两行；外层仍用 `PageHeader`，保留窄屏导航按钮和统一边距。编辑、删除是 `IconButton`（自带 aria-label 与 tooltip），立即运行是默认主按钮，运行中显示转圈并带 `aria-busy`。
   - 理由：用户在设计稿便签里点名了这套顶栏；`PageHeader` 保住了面包屑顶栏原本提供的导航触发器。
9. **窄屏堆叠用容器查询 `@4xl`**（工单 02）
   - 问题：方案写「< 980px 堆叠」，怎么实现、断点取多少。
   - 选择：滚动容器设 `@container`，`@4xl`（896px）起两栏；以下两个列容器变成 `display: contents`，各区块成为同一个 flex 列的兄弟，用 `order-1..4` 排成 状态 → 指令 → 运行记录 → 其余配置。
   - 理由：按内容区宽度而非视口判断，侧栏展开 / 桌面窄窗都对；`@4xl` 是仓库已有断点，896px 时每栏仍约 400px 够用，不另造 980 的任意值。
10. **下次运行的取值与显示**（工单 02）
   - 选择：纯函数 `earliestScheduledRun`：只看启用的时间表触发器，按时刻（非字符串）取最早的 `next_run_at`，用该触发器的时区格式化；自动化不是启用状态时不显示。
   - 理由：停用的触发器会保留旧的 `next_run_at`；暂停的自动化不会触发，显示下次运行是误导。
11. **指令折叠**（工单 02）
   - 选择：折叠高度 `max-h-32`（128px，约 5 行正文）；测内层未截断的高度，超过才显示「显示全部 / 收起」，短指令整段显示、无按钮；渐隐用 `mask-image`，不依赖背景色；`ResizeObserver` 随列宽重测。
   - 理由：短指令出现展开按钮是噪音；mask 在深浅色和不同底色上都成立。
12. **运行记录行的内容**（工单 02）
   - 选择：去掉原来单独的状态文字列，行为 状态图标 + 时间 + 摘要 + 来源 + 尾部；摘要依次取「已关联任务」/ 失败原因 / 状态文字（兜底，图标不单独出现）；摘要不是状态文字时给图标补一段 sr-only 状态。尾部：可跳任务的行显示右箭头；仅运行的行仍是原来的「查看执行日志」按钮（工单 03 改为进运行页）。
   - 理由：照设计稿 2.1 的列；状态信息对读屏仍可得；本票不改点击去向。
13. **详情页文案调整**（工单 02）
   - 选择：zh-Hans / zh-Hant 的「Prompt」改「指令」、「运行历史」改「运行记录」（繁体「執行紀錄」），对齐设计稿；其他语言原文不动。删掉不再使用的 `section_danger`、`section_properties`。触发器「添加」按钮可见文字用新键 `add`，可访问名沿用 `add_trigger`。
   - 理由：设计稿用「指令」「运行记录」；英文等原文本就是对应含义，不必改。
14. **Webhook 投递只换外框**（工单 02）
   - 选择：区块标题和列表容器改成与左栏其它区块一致（小号灰色标题、浅灰圆角底），每行内容与点开的详情不变。
15. **启停开关对只读用户的可见性不变**（工单 02）
   - 问题：工单只列了编辑 / 删除 / 立即运行 / 触发器增删改对只读用户隐藏，开关原来不按 `can_write` 隐藏。
   - 选择：保持原样（仍显示，归档时禁用），由后端把关。
   - 理由：只改布局不改行为。
16. **执行过程的渲染与数据**（工单 03）
   - 问题：执行过程怎么渲染成「智能体的一轮回复」，运行中怎么实时刷新。
   - 选择：从 `chat-message-list.tsx` 导出 `TaskTimelineReply`，内部复用聊天的 `TimelineView`（步骤折叠、最终回答、用时、复制），运行中折叠展开、结束后收起；数据用 core 已有的 `useTaskMessages(taskId, live)`，与 `TranscriptButton` 读同一份 `task-messages` 缓存（WS `task:message` 实时写入），挂载时和运行结束时各回填一次；运行中上方放聊天的 `TaskStatusPill`（阶段文字 + 计时）。用时取运行的 `completed_at − triggered_at`，失败运行显示「失败于」。
   - 理由：与聊天回复同一套样式和交互，工单 04 换成完整对话时不会出现两种回复样式；不自造实时逻辑。
17. **哪些运行记录进运行页**（工单 03）
   - 选择：「仅运行」自动化的每条没有关联任务的运行都整行链接到运行页（含跳过、派发前失败，运行页只显示触发与运行信息）；有 `issue_id` 的仍跳任务详情；「创建任务」自动化里没有任务的行保持不可点，与原来一致。
   - 理由：跳过 / 失败的运行原来只能看一行截断的原因，运行页能看全；「创建任务」模式按决策 11 不进运行页。
18. **运行信息面板的收起**（工单 03）
   - 选择：收起状态是组件内 state，不持久化，每次进入默认展开；窄于 `lg` 时面板堆到对话下方（最高半屏），与知识库作业页一致。
   - 理由：只是一次性查看的辅助信息，持久化收益小；窄屏堆叠沿用仓库已有做法。
19. **智能体栏与执行者**（工单 03）
   - 选择：智能体栏在运行页内实现（`ActorAvatar` + `useAgentPresenceDetail`，与知识库作业页的 `AgentRow` 同写法），没有把 kb 的 `AgentRow` 抽成公共组件；执行者取自动化当前的 `assignee`（运行响应不带智能体）；小队执行者只显示头像和名字，不显示运行时状态。
   - 理由：不为本票改 kb 代码；运行接口没有智能体字段，本票不做后端改动。
20. **加载失败的三种状态**（工单 03）
   - 选择：任一接口 403 → 「无权查看这次运行」；404 或无数据 → 「未找到这次运行」；其他错误 → 「运行加载失败」+ 重试。三种状态都保留顶栏返回按钮。
   - 理由：工单要求区分找不到与无权限；其余错误给出可恢复的路径。
21. **没有任务的运行**（工单 03）
   - 选择：对话区显示触发卡片和一行「本次运行未执行。」，失败原因在右侧运行信息里。
   - 理由：只放触发卡片时下方一片空白，像是没加载完。
22. **Webhook 载荷与事件名**（工单 03）
   - 选择：载荷只在来源是 Webhook 且有载荷时显示（与原弹窗一致），用现有 `WebhookPayloadPreview` 默认展开；触发卡片的元信息带上载荷里的事件名。
23. **配套清理**（工单 03）
   - 选择：`RUN_VISUAL` 抽到 `run-status.ts` 供详情页和运行页共用；删除 `RunRow` 的 `TranscriptButton`、`syntheticTask`、`WebhookPayloadSlot` 和不再使用的 `run.view_log` 文案（六种语言）；`diagnostics` 路由表补上运行页路由，避免诊断上报把它当未知路径。设计稿右侧「能查看这个自动化的成员共用这段对话。」属于对话能力，留给工单 04。
24. **迁移编号与 rebrand 顺延**（工单 04）
   - 选择：`646_autopilot_run_chat_session` 加列，`647_autopilot_run_chat_session_uidx` 建部分唯一索引（`WHERE chat_session_id IS NOT NULL`，同时服务从会话反查运行）；rebrand 顺延为 `648`，同步脚本 `KEEP`、`cmd/migrate` 并发索引表和仓库 `CLAUDE.md` 里的编号。仓库里没有测试引用 rebrand 文件名。
   - 理由：仓库迁移规则要求 rebrand 排最后、并发索引单独成文件。
25. **获取或创建对话的判定顺序与权限**（工单 04）
   - 选择：先查自动化（工作区成员可读，与运行详情同一道门）→ 运行属于该自动化（否则 404）→ `run_only`（否则 409 `run_mode_unsupported`）→ 有任务（否则 409 `run_has_no_session`）→ 对运行任务的智能体做 `canInvokeAgent`（否则 403）→ 已有会话直接返回 → 任务未到终态（completed / failed / cancelled）返回 409 `run_in_progress`。已有会话的返回放在运行中判定之前，工单 05 放开运行中时不用再挪。事务内先 `FOR UPDATE` 锁运行行、再拿工作区 `FOR KEY SHARE`（与所有建会话路径一致）和项目锁；项目已删除时会话不挂项目，不报错。
   - 理由：工单要求；锁运行行保证并发首发只建一个会话。
26. **新会话标记为显式创建**（工单 04）
   - 问题：普通聊天接口（发消息、拉消息）只认「显式创建或已有非指令消息」的会话；对话在第一次发送前才建，建好时是空的，不标记就发不进去。
   - 选择：建会话后调用 `MarkChatSessionExplicitlyCreated`，与聊天页新建会话一致（知识库作业建会话时同时写入首条消息，所以没标记）。
   - 影响：这类会话会出现在创建者的聊天列表里，排除留给工单 06。
27. **续接指针的预填**（工单 04）
   - 选择：用运行任务的 `session_id / work_dir / runtime_id` 调 `UpdateChatSessionSession`；任务失败且 `service.ResumeUnsafeFailure(failure_reason, error)` 为真（与 `GetLastTaskSession` 的黑名单和错误文本守卫同源），或任务的 `retired_session_id` 就是它的 `session_id` 时，只填 `work_dir` 和 `runtime_id`。
28. **运行响应带执行智能体**（工单 04）
   - 选择：运行详情接口按 `task_id` 取任务，返回 `agent_id`（`omitempty`，列表不带，避免逐行查任务）；`chat_session_id` 随行数据在详情和列表都返回。运行页执行者、回复头像、运行信息里的执行者都优先用 `agent_id`，旧服务端没有时回退到自动化当前的 assignee。运行详情接口改为过 `AutopilotRunSchema`（之前直接 `as` 返回）。
   - 理由：补工单 03 决策 19 的缺口；对话只能发给运行实际用的智能体。
29. **运行页对话的组合方式**（工单 04）
   - 问题：第一轮（触发卡片 + 执行过程）和追问消息要读成一段对话，但 `ChatMessageList` 自带虚拟滚动容器。
   - 选择：给 `ChatMessageList` 加可选 `header`，通过 Virtuoso 上下文渲染在第一条消息之上（还有更早的分页未加载时不显示，避免第一轮悬在缺口上方）。有追问消息时第一轮作为 `header` 进聊天列表，整页一个滚动容器、打开落在最新消息；还没有追问时沿用工单 03 的普通滚动区。
   - 理由：空列表时聊天列表要等「到达底部」的兜底计时才显示，直接用会让运行页首屏空白一段时间；改动只加一个可选 prop，聊天页不受影响。
30. **运行未结束时的输入框**（工单 04）
   - 选择：显示输入框但禁用，占位文字「运行结束后开放追问」（六种语言，`run_page.followup_after_run`）。`ChatInput` 加可选 `disabledPlaceholder`，优先级低于智能体归档 / 无权限 / 未绑定运行时的占位文字。工单 05 放开后删掉这个分支即可。
   - 理由：`ChatInput` 禁用时默认占位是「会话已归档」，语义不对。
31. **草稿与恢复**（工单 04）
   - 选择：草稿和编辑器 key 都是 `autopilot-run:{runId}`，与普通聊天隔离，且会话建出来前后草稿不换槽。停止一轮后恢复草稿的请求原本按会话 ID 定位，`useAutopilotRunConversation` 把它改投到这个草稿槽。附件上传在可发送时开启（与聊天页一样只在无权限时关闭）。
32. **横幅与禁用条件**（工单 04）
   - 选择：照聊天窗口的单槽优先级：无权限 > 智能体已归档 > 未绑定运行时 > 离线 / 不稳定；智能体从工作区智能体列表（含已归档）取，权限用 `canAssignAgent`。执行者是小队（旧服务端没有 `agent_id` 且 assignee 是小队）时不显示输入框。
33. **运行信息里的「共用这段对话」**（工单 04）
   - 选择：本票不加。对话目前只对创建者可用，这句话在工单 06 放开共用访问时一起加。
34. **运行结束写指针的挂点**（工单 05）
   - 问题：方案写在 `SyncRunFromTask` 所在路径；工单建议放在 Complete / Fail 的同一事务。
   - 选择：放进 `SettleTerminalTaskState`（`service/autopilot_run_chat.go` 的 `pinAutopilotRunChatSessions`）。它是所有终态写入（完成、失败、取消、清扫、批量取消）在同一事务里必经的入口，所以运行任务被停止或被清扫判失败时也会写。只处理带 `autopilot_run_id` 的任务，没有就不查库；先按运行 ID 批量 `FOR KEY SHARE` 锁运行行取 `chat_session_id`，再用一条 `UpdateChatSessionSessions`（unnest 批量更新，COALESCE 语义同 `UpdateChatSessionSession`）写入，不在循环里查库。指针内容复用工单 04 的规则，函数移到 service 改名 `RunChatResumePointer`，接口和写指针共用。
   - 理由：指针和放行排队消息的状态翻转同一事务提交，认领不可能先于指针。不选 `SyncRunFromTask`：它在事务外异步执行，任务翻成终态后、指针写好前有窗口，排队消息会被认领并以空会话开跑。
35. **获取或创建对话与运行结束的并发**（工单 05）
   - 选择：运行中也创建会话，不预填；任务在运行行 `FOR UPDATE` 锁内重读，已到终态才预填。终态事务对运行行取 `FOR KEY SHARE`（与 `FOR UPDATE` 冲突、与运行状态更新的 `NO KEY UPDATE` 不冲突），且不按 `chat_session_id` 过滤，等锁后读到最新版本。
   - 理由：两边任一先提交，另一边都能看到对方的结果，不会出现「会话建好但指针永远为空」。删掉 `run_in_progress` 错误码和对应测试。
36. **认领时的阻塞范围**（工单 05）
   - 选择：`ClaimAgentTask` 的 `NOT EXISTS` 按 `autopilot_run_id` 关联运行的全部任务判断（未结束集合 `queued / dispatched / running / waiting_local_directory / deferred`），而不只看 `autopilot_run.task_id`。只改这一条：它是唯一带串行化判断的认领查询，按运行时 / 批量认领的候选查询最终都走它，被挡的候选与其他串行化一样被跳过。用到 `autopilot_run_chat_session_uidx` 和 `(autopilot_run_id, created_at)` 部分索引。
   - 理由：运行任务可重试失败时自动重试子任务带同一 `autopilot_run_id`，而 `task_id` 仍指向父任务；只看 `task_id` 会让追问在重试跑之前被认领。
37. **运行中排队的前端呈现**（工单 05）
   - 选择：运行中服务端的队首（仍是 `queued`）也当作排队消息：放进 `ChatQueue` 的第一行（内容取它的用户消息），对话里不显示；队首已离开 `queued` 时照常是进行中的一轮（`queueFollowUpsBehindRun`）。运行中「立即发送」不可用（不传队首状态）；「清空」同时移除这条队首，因为服务端清空只清队首之后的消息。
   - 理由：设计稿 3.3 运行中发出的消息都在排队框里；运行结束后照聊天页的队首 / 排队逻辑继续。
38. **运行中的「停止」**（工单 05）
   - 选择：运行中输入框按钮与聊天页一致（空内容「停止」、有内容「排队发送」）；「停止」停的是运行任务本身，调 `cancelTaskById`（智能体活动页取消自动化任务用的同一接口），失败只记日志，与聊天页停止一致。删掉 `ChatInput` 的 `disabledPlaceholder` 和六种语言的 `run_page.followup_after_run`。
   - 理由：设计稿 3.2「正在工作，输入框按钮为停止」，此时进行中的一轮就是运行本身。
39. **共用访问的判定**（工单 06）
   - 选择：「能查看该自动化」= 会话挂在本工作区某自动化的运行上，且调用者是该工作区成员（自动化的读权限就是工作区成员，与运行详情同一道门）。在 `loadChatSessionForUser` 里放行，走它的接口随之放开：单会话读取、拉消息、发送、停止、排队（读 / 插队 / 清空）、草稿恢复、标记已读、快捷动作刷新、附件上传。私有智能体的查看门 `canAccessPrivateAgent` 和每次发送的 `canInvokeAgent` 仍按请求人判断；追问任务的 `initiator_user_id` 是发送人（`SendDirectChatMessage` 现有行为，已测）。看不到的运行会话返回 404；普通聊天的非创建者仍是 403。
40. **仅创建者的操作**（工单 06）
   - 选择：重命名 / 改项目、置顶、归档、删除对共用成员返回 403（`requireChatSessionCreator`），创建者行为不变。
   - 理由：这些改的是会话本身，会影响所有共用者；运行会话不在聊天列表里，界面上也没有这些入口。
41. **停止与排队消息的操作**（工单 06）
   - 选择：`CancelTaskByUser` 原本只给会话创建者，对运行会话改为共用成员都能停止当前轮、编辑或移除排队消息，与走会话门的「清空排队」一致；编辑或停止拿回的提示词回到操作者自己的输入框。
   - 理由：决策 10「多人同时发消息靠会话自带的排队」，排队是会话级的。
42. **草稿恢复按发送人**（工单 06）
   - 选择：运行会话里 `chat_draft_restore` 只返回、只消费任务发起人是自己的那条（在 SQL 里按 `autopilot_run` 判断，普通会话不变）。
   - 理由：草稿恢复是持久化的，运行页打开时会自动填进输入框；不按人过滤，B 打开运行页会拿到 A 被停下的提示词并把它消费掉。
43. **发送人的取法**（工单 06）
   - 选择：不改 `ListChatMessages` / `ListChatMessagesPage` 的返回类型，新增 `ListChatMessageSenders`，按当前页用户消息的 `task_id` 批量取 `initiator_user_id`（每页一条查询）；只给用户消息填 `sender_user_id`，助手消息为 null。`chat:message` 事件也带 `sender_user_id`，运行页本地乐观写入带当前用户。
   - 理由：这两个查询的 `db.ChatMessage` 行被可见性过滤、分页裁剪、快捷动作上下文、渠道历史和大量测试直接复用，改成联表的行类型牵连面大；批量查询同样不加列、不在循环里查库。
44. **运行页的发送人展示**（工单 06）
   - 选择：`ChatMessageList` 加可选 `renderUserMessageSender`，只有运行页传入；头像 + 名字在气泡上方右对齐（设计稿 3.4），用 `ActorAvatar` / `useActorName`。缺省回退会话创建者（`chatSessionOptions` 取 `creator_id`）。普通聊天页不传，保持现状。右侧运行信息在有对话能力时（有任务、执行者是智能体）显示「能查看这个自动化的成员共用这段对话。」。
45. **聊天侧排除的范围**（工单 06）
   - 选择：`ListChatSessionsByCreator` / `ListAllChatSessionsByCreator`（未读数由列表派生，随之排除）、`ListPendingChatTasksByCreator` / `HasPendingChatTasksByCreator`（浮动入口运行中指示）加 `NOT EXISTS (… autopilot_run …)`。
   - 不排除：快捷动作生成（运行页渲染快捷动作，知识库作业会话也照常生成）；`scope=workspace` 的全工作区会话读取（owner 给知识库摄取用，知识库作业会话同样没排除）；首条消息自动起标题（标题不展示，无副作用）。
46. **实时订阅的授权**（工单 06）
   - 选择：`cmd/server/scope_authorizer.go` 的 chat 和聊天任务 scope 同步放开运行会话（同工作区即可）。
   - 理由：按 scope 路由目前未启用（事件仍按工作区广播，共用成员现在就能收到），但授权与 HTTP 门不一致会在日后开启时让共用成员收不到消息。
47. **删除自动化时归档对话**（工单 06）
   - 选择：在 `DeleteAutopilot` 的同一事务里执行一条 `ArchiveAutopilotRunChatSessions`（`UPDATE chat_session … FROM autopilot_run`）。删除自动化本身是归档（软删），运行和会话都保留、可读；不取消已排队的追问，与归档网页聊天一致。
   - 缺口：运行页对已删除自动化不额外禁用输入框，发送会被服务端以「会话已归档」拒绝。

   - 选择：运行任务已终态时，按 `autopilot_run_id` 取该运行最新一条带 `session_id` 的终态任务（自动重试子任务）作续接指针；没有就用运行任务本身（失败未建会话时只填工作目录，同前）。
