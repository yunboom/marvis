Marvis Desktop 提供 macOS、Windows 和 Linux 版本。它和 Web 版使用相同的账号与工作区数据，但会在本机自动管理守护进程，并为不同工作区保留各自的标签页。

## Desktop 与 Web

| | Web | Desktop |
| --- | --- | --- |
| 打开方式 | 浏览器 | 安装桌面应用 |
| 工作区标签页 | 使用浏览器标签页 | 每个工作区保留独立的一组标签页 |
| 守护进程 | 需要单独安装并启动 CLI | 登录后由应用自动启动 |
| 更新 | 刷新页面 | 通过桌面应用更新 |

临时查看或在公共电脑上使用时，Web 更方便。

两者可以同时登录。只要连接的是同一个 Marvis 服务，看到的数据就是共享的。

## 安装

<Steps>
<Step>
从 [Marvis 下载页](https://marvis.ai/download) 选择与系统和处理器架构对应的安装包：

| 平台 | 安装包 |
| --- | --- |
| macOS | `.dmg` |
| Windows | `.exe` |
| Linux | `.AppImage`、`.deb` 或 `.rpm` |
</Step>
<Step>
安装后，[把 Desktop 连接到 Marvis 服务器](#连接服务器)并登录。登录后，Desktop 会启动自己内置的 Marvis CLI，并检测本机已有的 AI 编程工具。
</Step>
</Steps>

<Callout type="info">
Desktop 内置的 CLI 只供应用管理运行时使用。如果你还要在终端中运行 `marvis issue` 等命令，按[快速上手第 2 步](/cloud-quickstart#2-连接一台电脑)单独安装 CLI。
</Callout>

## 桌面标签页

Desktop 会为每个工作区单独保存标签页。例如，你在工作区 A 打开了三个任务，切到工作区 B 后会看到 B 自己的标签页；切回 A 时，之前的三个标签页仍然保留。

<DesktopTabsDemo />

同一资源只会在当前工作区打开一次。标签页可以重新排序、固定、关闭，也会保留各自的前进、后退和滚动位置。固定的标签页排在最左边，没有关闭按钮，要先取消固定才能关；在它里面打开别的页面时会新开一个标签页，它自己停在原页面。点击或粘贴本部署的应用链接会直接在标签页中打开，不会跳转到浏览器。

退出登录会清除本机保存的所有标签页，避免下一位登录者看到上一个账号留下的页面。

## 内置守护进程

登录后，Desktop 会为当前 Marvis 服务创建一个专用 CLI profile，并用它启动守护进程。这个 profile 位于：

```text
~/.marvis/profiles/desktop-<host>/
```

它不会读取或覆盖你在终端中使用的默认 profile。如果你同时手动启动了另一个守护进程，Marvis 会把它们显示为不同的运行时。

可以在 Desktop 的设置中查看运行状态和日志。工具没有被检测到时，先确认它能在普通终端中运行并且已经登录，再重启 Desktop 的守护进程。

## 更新 Desktop

自动更新默认开启。应用在后台检查并下载新版本，下载完成后可以立即重启安装，也可以等下次退出时安装。在 **设置 → 更新** 中可以关闭自动检查，或手动检查新版本。

更新按操作系统和处理器架构分发：

- Windows arm64 和 macOS x64（Intel）使用各自独立的更新源；
- 其余架构使用默认更新源；
- 应用会自动匹配更新源，无需手动选择；
- Linux 上自动更新只对 `.AppImage` 生效，`.deb` 和 `.rpm` 通过下载新安装包覆盖安装；
- 自动更新失败时，同样从下载页获取对应安装包覆盖安装。

## 连接服务器

Desktop 连接 Marvis 服务器，也就是后端。部署时同时部署网页端：Google 和飞书登录、**复制链接**都经过网页端。

### 首次启动

没有配置服务器时，Desktop 显示**连接到 Marvis 服务器**。

1. 在**局域网中的服务器**里选一台，或输入地址。默认地址是 `http://marvis.local:13840`。
2. 输入地址时，点**测试连接**。Desktop 显示服务器名称和版本，或无法连接的原因。
3. 点**继续**，在确认页核对地址，再点**连接**。
4. 登录。

列表随服务器上线、下线实时更新，点**重新查找**可再次查找。电脑和服务器需要在同一个局域网。运行在本机的服务器标有**本机**。版本过旧的服务器会显示，但不能选择。

确认之前 Desktop 不会连接，也不会自动登录。使用 HTTP 的服务器不加密，确认页会提示这一点。

选定的服务器以 `server.json` 保存在 Desktop 的应用数据目录：

| 平台 | 路径 |
| --- | --- |
| macOS | `~/Library/Application Support/Marvis/` |
| Linux | `~/.config/Marvis/` |
| Windows | `%APPDATA%\Marvis\` |

### 切换服务器

打开**设置 → 本设备 → 服务器**。页面包含：

- 当前服务器的名称、地址和连接状态；
- 局域网中找到的其他服务器，每台带**切换**；
- **其他地址**输入框，带**测试连接**和**切换**。

切换会退出当前账号。Desktop 先请你确认，再保存新服务器并进入登录页。内置守护进程自动改用新服务器对应的 profile。

这项设置只影响这台电脑。

### 连接中断

- 服务器停止响应时，主区顶部出现横幅，提示连接已断开，正在重新连接。
- 多次失败后，横幅提示无法连接服务器，并提供**重试**和**切换服务器**。Desktop 继续检查，服务器恢复后自动回到在线。
- 从局域网列表选的服务器按 IP 地址保存。这个地址不再应答，而局域网里同一台服务器（按实例 ID 识别）出现在新 IP 时，Desktop 改用新地址，并提示已重新连接。
- 保存的地址上换了另一台服务器时，Desktop 弹出**这个地址上换了一台服务器**，不会自动切换。选择**继续等待**或**切换服务器**。

### 没有网页端

服务器没有网页地址，或网页地址是 `localhost` 时，Desktop 按没有网页端处理。部署的服务器不应处于这种状态，它出现在本地开发中：

- 登录页隐藏 Google 按钮。服务器配置了飞书登录，并把 `MARVIS_LARK_LOGIN_DESKTOP_REDIRECT_URI` 设为在飞书开发者后台登记过的后端回调地址时，保留飞书按钮。点击后在浏览器里完成飞书登录，再回到 Desktop。否则只保留邮箱验证码登录；
- **复制链接**生成 `marvis://open?...` 链接，在装有 Desktop 且连接同一台服务器的电脑上，链接会在 Desktop 里打开。

## 用 desktop.json 预置服务器

运维人员可以为一台电脑预置服务器。Desktop 只在应用里还没有选定服务器时读取预置，直接连接，不显示连接页，也不会写入这个文件。

在用户目录的 `.marvis` 下创建 `desktop.json`，内容如下：

```json
{
  "schemaVersion": 1,
  "apiUrl": "https://api.example.com"
}
```

<Tabs groupId="os" persist items={["macOS / Linux", "Windows"]}>
<Tab value="macOS / Linux">

| 平台 | 路径 |
| --- | --- |
| macOS | `/Users/<你>/.marvis/desktop.json` |
| Linux | `/home/<你>/.marvis/desktop.json` |

</Tab>
<Tab value="Windows">

文件路径是 `C:\Users\<你>\.marvis\desktop.json`。

记事本和 PowerShell 重定向容易生成 Desktop 读不了的文件（原因见[Windows：检查文件名和编码](#windows检查文件名和编码)），建议在 PowerShell 里一步创建：

```powershell
$dir = "$env:USERPROFILE\.marvis"
New-Item -ItemType Directory -Force $dir | Out-Null
$json = @'
{
  "schemaVersion": 1,
  "apiUrl": "https://api.example.com"
}
'@
[System.IO.File]::WriteAllText("$dir\desktop.json", $json)
```

</Tab>
</Tabs>

以上是默认位置。用户目录被迁移或重定向过的话，用实际路径。

<Callout type="warning">
这个文件**不是** CLI 的 `~/.marvis/config.json`，字段名也不同：CLI 用 `server_url`，Desktop 用 `apiUrl`。Desktop 不会读取 CLI 的配置，它在 `~/.marvis/profiles/desktop-<host>/` 下管理独立的 daemon profile。改 `config.json` 不会影响 Desktop 连接哪个服务。
</Callout>

`apiUrl` 是 backend 的公开地址，必须填写，且必须使用 `http` 或 `https`。另外两个地址可以省略，Desktop 会自动推导：

- `wsUrl`：把 `apiUrl` 的协议换成 `ws` 或 `wss`，并在路径后追加 `/ws`；
- `appUrl`：域名以 `api.` 开头且至少三段时去掉 `api.` 前缀（`api.example.com` → `example.com`），否则保持与 `apiUrl` 相同。

预置的配置一定带网页地址，省略 `appUrl` 时由 Desktop 推导。

通常只写 `apiUrl` 即可。推导不符合预期时再显式覆盖，常见情况有三类：

- Web 与 API 不同域；
- WebSocket 单独部署；
- 域名不满足剥前缀的约定（`api.local` 这类两段域名不会去掉前缀）。

```json
{
  "schemaVersion": 1,
  "apiUrl": "https://api.example.com",
  "appUrl": "https://app.example.com",
  "wsUrl": "wss://ws.example.com/socket"
}
```

保存后重启 Desktop，配置只在启动时读取一次。两种失败的表现不同：

- **文件没找到**（目录不对，或文件名不是 `desktop.json`）：Desktop 显示连接页，不报错。所以如果 Desktop 仍然要求连接服务器且没有任何配置错误，说明文件不在 Desktop 查找的位置。
- **文件找到但无效**（JSON、版本或 URL 有问题）：Desktop 显示配置错误。

删除该文件并重启即可回到连接页。如果已在应用里选过服务器，还需要删除应用数据目录里的 `server.json`。

<Callout type="warning">
Desktop 只能连接浏览器和执行电脑都能访问的地址。远程自托管实例未使用 HTTPS 或未代理 WebSocket 时，Desktop 无法建立连接；完整配置见[自托管快速上手](/self-host-quickstart#remote-access)。
</Callout>

### Windows：检查文件名和编码

Windows 上两种常见的写文件方式会生成 Desktop 读不了的文件：

- **记事本会补 `.txt` 后缀**。存成 `desktop.json` 可能实际得到 `desktop.json.txt`，Desktop 会当作没找到。在资源管理器里打开文件扩展名显示，或在保存对话框里选*所有文件*。想确认真实文件名，在 PowerShell 里运行 `Get-ChildItem "$env:USERPROFILE\.marvis" -Filter "desktop.json*"`，`Name` 一列必须正好是 `desktop.json`。
- **PowerShell 重定向会写成 UTF-16 或带 BOM**。`> desktop.json` 和 `Out-File` 可能生成无法解析的编码，表现为配置错误。

上面 Windows 页签里的 PowerShell 命令可以同时避开这两个坑。

## Windows Defender 把 Marvis 报成病毒

Windows 安全中心报出 `Trojan:Script/Wacatac.B!ml` 之类的威胁，并隔离 Desktop 安装目录里的某个文件。被隔离的通常是内置的 CLI，而不是应用主程序：

```text
C:\Users\<你>\AppData\Local\Programs\@marvisdesktop\resources\app.asar.unpacked\resources\bin\marvis.exe
```

这是误报。`!ml` 后缀表示结论来自 Defender 的机器学习启发式判断，不是病毒特征库匹配。Marvis 的 Windows 构建目前还没有做 Authenticode 代码签名，一个刚发布、没有签名、又会拉起后台进程并建立网络连接的二进制，很容易被这类启发式判为可疑。所有 Windows 产物都由 GitHub Actions 从本仓库的公开源码构建。

你可以自己校验：每个 GitHub release 都发布了覆盖全部 CLI 压缩包的 `checksums.txt`。

```powershell
Get-FileHash .\marvis-cli-<version>-windows-amd64.zip -Algorithm SHA256
```

把输出的哈希和[最新 release](https://github.com/yunboom/marvis/releases/latest) 里 `checksums.txt` 对应那一行比对。

按下面三步处理：

<Steps>
<Step>
把隔离的文件恢复回来：Windows 安全中心 → *病毒和威胁防护* → *保护历史记录* → 选中 Marvis 那一条 → *操作* → *还原*。
</Step>
<Step>
加排除项，避免再次被隔离：*病毒和威胁防护* → *管理设置* → *排除项* → *添加或删除排除项* → *文件夹*，两个都要加：

- `%LOCALAPPDATA%\Programs\@marvisdesktop`
- `%APPDATA%\Marvis`

两个路径缺一不可：内置 CLI 被删掉后，Desktop 会把替换版本下载到 `%APPDATA%\Marvis\bin`，只排除安装目录的话，下载下来的副本还会再被隔离一次，陷入循环。
</Step>
<Step>
把误报提交给微软：在 [Microsoft Security Intelligence 文件提交页](https://www.microsoft.com/en-us/wdsi/filesubmission)选择 *Software developer* 和 *Incorrectly detected as malware*。只有这一步能让检测对所有用户撤销，一般几天内生效。
</Step>
</Steps>

<Callout type="warning">
只有在你是从[下载页](https://marvis.ai/download)或 [GitHub releases](https://github.com/yunboom/marvis/releases) 安装、且校验和对得上的前提下，才加这些排除项。排除项会关闭该文件夹内所有文件的实时保护。
</Callout>
