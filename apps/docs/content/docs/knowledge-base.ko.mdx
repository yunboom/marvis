지식 베이스는 태스크, 대화, 코드, 문서에 흩어진 팀 지식을 페이지로 정리합니다. 페이지는 에이전트가 쓰고 유지하며, 모든 사실에 출처가 붙습니다. 멤버는 읽고 주석을 달고 검토하며, 변경은 검토와 병합을 거친 뒤에만 반영됩니다.

<Callout type="info">
멤버는 화면에서 페이지를 직접 편집할 수 없습니다. 내용을 바꾸려면 주석을 달거나 [지식 베이스 작업](#jobs)으로 에이전트에게 맡기세요.
</Callout>

## 변경이 지식 베이스에 들어가는 과정 [#flow]

모든 변경은 같은 경로를 거칩니다.

1. 에이전트가 **초안**에서 페이지를 추가, 수정, 이동, 삭제합니다.
2. 초안이 제출 전 검사를 통과하면 **검토 제출**해 변경 요청을 만듭니다.
3. 멤버가 검토하고 관리자가 **병합**합니다. 페이지가 업데이트되고 이전 버전은 페이지 기록에 남습니다.

병합되기 전까지 초안은 작성자와 권한이 있는 사람만 볼 수 있고, 정식 페이지에는 영향이 없습니다.

## 지식 베이스 만들기 [#create]

사이드바에서 **지식 베이스**를 엽니다. 워크스페이스에 아직 없으면 **새 지식 베이스**를 누르고, 이미 있으면 왼쪽 위의 지식 베이스 전환기나 **⋯** 메뉴에서 만듭니다.

만들기 화면 왼쪽은 **지식 베이스 빌더**와의 대화, 오른쪽은 설정입니다.

1. 빌더가 사용할 런타임과 모델을 고릅니다.
2. 시작 카드(개발, 테스트, 제품, 팀 전체, 에이전트 팀 기억, 기타)를 고르거나 원하는 지식 베이스를 설명합니다. 빌더가 독자와 용도를 묻고 오른쪽에 채워 넣습니다.
3. 오른쪽 설정을 확인하고 **만들기**를 누릅니다.

| 설정 | 설명 |
|---|---|
| 이름, 소개 | 전환기와 홈에 표시됩니다. |
| 디렉터리 이름 | 지식 베이스의 slug입니다. 소문자, 숫자, 하이픈만 쓸 수 있고 만든 뒤에는 바꿀 수 없습니다. |
| 목적 | 누가 읽는지, 무엇을 다루고 무엇을 다루지 않는지, 주요 용도입니다. 에이전트가 페이지를 쓸 때 참고합니다. |
| Schema | 페이지 구성과 작성 방식입니다. **기본**은 내장 Schema로 읽기 전용이고, **사용자 지정**은 자유롭게 작성할 수 있습니다. 새로 만들면 빈 사용자 지정 Schema로 시작합니다. |

**생성 취소**를 누르면 대화와 설정이 함께 삭제됩니다. 끝내지 않은 생성은 남아 있어 나중에 이어서 할 수 있습니다.

만든 뒤 홈에는 처음 할 일로 자료 수집, 검토 후 반영, 읽고 주석 달기, 정기 유지 관리 설정이 안내됩니다.

### 설정 바꾸기

**⋯** 메뉴의 **지식 베이스 설정**에서 빌더와 대화를 이어 가거나 목적과 Schema를 직접 고친 뒤 **저장**하면 바로 반영됩니다. 지식 베이스를 만든 사람과 워크스페이스 `owner`, `admin`만 설정을 바꿀 수 있습니다.

## 지식 베이스 둘러보기 [#browse]

**지식 베이스**를 열면 마지막으로 본 지식 베이스로 돌아갑니다. 왼쪽 열은 위에서부터 다음과 같습니다.

- **지식 베이스 전환기**: 지식 베이스마다 대기 중인 항목 수를 보여 줍니다.
- **⋯ 메뉴**: 새 지식 베이스, 지식 베이스 설정, 지식 베이스 관리, 검토, 변경 기록, 링크 복사.
- **홈**, **지식 베이스 작업**, **관계도**.
- **페이지**: 페이지 트리.

### 홈

홈에는 소개와 **대기** 중인 세 가지 항목이 표시됩니다.

- **검토 대기 변경**: 검토를 기다리는 변경 요청.
- **주석**: 처리되지 않은 주석. 에이전트가 보고한 빈틈도 포함됩니다.
- **재검토가 필요한 페이지**: 재검토 기한이 지난 페이지.

아래의 **최근 업데이트**에는 최근 병합된 변경이 나열됩니다. 검토 대기 변경이 있으면 사이드바의 **지식 베이스**에 개수가 표시되고, 누르면 바로 검토로 이동합니다.

### 페이지 읽기

페이지의 사실마다 번호가 매겨진 인용이 붙고, 마우스를 올리면 출처(태스크, 대화, 풀 리퀘스트, 코드, 파일, 웹 페이지)가 보입니다. 코드 출처는 확인한 버전과 줄 번호를 보여 주고, 대화 출처는 대화를 시작한 사람만 열 수 있습니다. 페이지 끝의 **출처**에 전체 목록이 있습니다.

페이지 위쪽에는 패널 전환 버튼이 세 개 있습니다.

- **이 페이지의 주석**: 이 페이지의 주석을 보고 추가합니다.
- **목차**: 페이지의 제목 구조.
- **페이지 정보**: 다음 재검토일, 영역, 출처 수, 이 페이지를 링크하는 페이지.

**더 보기** 메뉴에는 **페이지 기록**, **에이전트에게 이 페이지 점검 요청**, **링크 복사**가 있습니다.

아직 작성되지 않은 페이지로 가는 링크에는 그렇다고 표시됩니다. 페이지 트리의 위치에서 **+**를 누르고 **에이전트에게 여기에 페이지 작성 요청**을 고른 뒤 쓸 내용을 적으면 작업이 만들어집니다.

내 초안이 지금 페이지를 바꾸고 있으면 위쪽 막대에서 **정식**과 **초안**을 전환하고 **차이 표시**를 켤 수 있습니다.

### 검색

- 홈의 검색창은 현재 지식 베이스만 검색하고, 일치하는 단락으로 바로 이동합니다.
- 지식 베이스 어디서든 <kbd>⌘</kbd> <kbd>Shift</kbd> <kbd>F</kbd>(Windows / Linux는 <kbd>Ctrl</kbd> <kbd>Shift</kbd> <kbd>F</kbd>)를 누르면 모든 지식 베이스를 검색합니다.
- 페이지에서 <kbd>⌘</kbd> <kbd>F</kbd>를 누르면 페이지 안의 글자를 찾습니다.

기본은 키워드 검색만 합니다. 자체 호스팅 인스턴스에서 `MARVIS_EMBEDDING_BASE_URL`, `MARVIS_EMBEDDING_API_KEY`, `MARVIS_EMBEDDING_MODEL`을 모두 설정하고 Postgres에 pgvector 확장이 있으면 의미 검색이 더해집니다. OpenAI 호환 `/v1/embeddings`로 1024차원 벡터를 반환하는 모델이면 됩니다.

<Callout type="warning">
의미 검색을 켜면 병합된 페이지의 본문과 모든 검색어가 embedding 서비스로 전송됩니다. 초안은 전송되지 않습니다.
</Callout>

### 관계도

왼쪽 열의 **관계도**는 페이지 사이의 링크로 지식 베이스 전체를 그리고, 최상위 페이지별로 색을 구분합니다. 링크가 없는 페이지와 아직 작성되지 않은 페이지는 점선으로 표시됩니다. 노드를 누르면 페이지가 열립니다.

## 주석 [#annotations]

내용이 틀렸거나 빠졌거나 오래됐다면 주석을 남기세요. 에이전트가 작업할 때 읽습니다. 주석 범위는 세 가지입니다.

| 범위 | 추가 방법 |
|---|---|
| 한 문장 | 페이지에서 글자를 선택하고 **주석**을 누릅니다. 에이전트가 원래 문장을 봅니다. |
| 한 페이지 | **이 페이지의 주석**을 열고 **주석 추가**를 누릅니다. |
| 지식 베이스 전체 | 홈에서 **지식 베이스 주석**을 열고 **주석 추가**를 누릅니다. |

주석 상태:

| 상태 | 의미 |
|---|---|
| **대기 중** | 아직 처리한 변경이 없습니다. |
| **처리 중** | 변경 요청이 처리했고 병합을 기다립니다. 그 변경 요청이 닫히면 대기 중으로 돌아갑니다. |
| **해결됨** | 처리한 변경 요청이 병합되었습니다. |
| **처리 안 함** | 바꾸지 않기로 했습니다. **되돌리기**로 대기 중으로 돌릴 수 있습니다. |

주석 작성자, 지식 베이스를 만든 사람, `owner`, `admin`은 주석을 처리 안 함으로 바꾸거나 되돌릴 수 있습니다.

원래 문장이 고쳐지면 주석은 새 문장을 따라가고, 삭제되면 당시의 원문을 남깁니다.

**에이전트에게 맡기기**로 주석 하나를 넘길 수 있고, 주석 패널에서 대기 중인 주석을 한꺼번에 넘길 수도 있습니다. 어느 쪽이든 주석을 처리하는 작업이 만들어집니다.

## 지식 베이스 작업 [#jobs]

작업은 지식 베이스에 쓰는 주된 방법입니다. 에이전트와 대화하면 에이전트가 초안에서 페이지를 고치고, 여러분이 확인한 뒤 검토에 제출합니다.

왼쪽 열에서 **지식 베이스 작업**을 열고 **새 작업**을 누릅니다.

1. **실행 에이전트**를 고릅니다. 사용 권한이 있고 런타임을 쓸 수 있는 에이전트만 표시됩니다.
2. 시작 카드를 고르거나 할 일을 설명합니다.

| 작업 | 하는 일 |
|---|---|
| **자료 수록** | 태스크, 대화, 코드, 파일, 웹 페이지의 지식을 페이지로 씁니다. 에이전트가 먼저 무엇을 수록할지 묻습니다. |
| **상태 점검** | 오래된 내용, 모순, 빈틈을 찾아 주석으로 기록합니다. 페이지를 직접 고치지 않습니다. |
| **지식 병합** | 중복되거나 겹치는 페이지를 합칩니다. |
| **주석 처리** | 주석에 맞춰 페이지를 고칩니다. |
| **예약 수집 만들기**, **예약 상태 점검 만들기** | 에이전트가 일정에 따라 실행되는 [오토파일럿](/autopilots)을 만듭니다. 이후에는 오토파일럿 페이지에서 관리합니다. |

주석, **에이전트에게 이 페이지 점검 요청**, 페이지 트리의 **+**, 원본 자료, 재검토 목록에서도 해당 내용을 담은 작업을 바로 만들 수 있습니다.

작업 화면 왼쪽은 대화로, 언제든 요청을 더하거나 멈출 수 있습니다. 오른쪽 **초안 변경**에는 추가, 수정, 이동, 삭제된 페이지와 **제출 전 검사** 결과가 나옵니다.

- **오류**는 고쳐야 제출할 수 있습니다. 예: 페이지 머리말에 필수 항목이 없음, 사실에 출처가 없음, 같은 단계에 같은 이름의 페이지가 있음, 해결되지 않은 충돌이 있음.
- **경고**는 제출을 막지 않습니다. 예: 코드 출처에 버전이 없음, 아직 작성되지 않은 페이지로 링크함.

검사 문제는 **에이전트에게 수정 요청**으로 처리합니다. 그사이 메인라인에 충돌하는 변경이 생겼다면 **에이전트에게 메인라인 기준 업데이트 요청**을 누릅니다.

문제가 없으면 **검토 제출**을 누릅니다. 에이전트의 턴이 끝나야 하고, 초안을 만든 사람만 제출할 수 있습니다. 제출하면 초안은 읽기 전용이 됩니다. **초안 버리기**를 누르면 변경은 버려지고 작업은 목록에 남습니다.

작업은 시작한 사람만 보고 열 수 있습니다. 목록은 실행 중, 실패로 거를 수 있습니다. 필요 없는 작업은 보관할 수 있고, 보관한 작업만 삭제할 수 있습니다. 삭제하면 대화도 지워지고 제출하지 않은 초안은 버려집니다.

## 검토와 병합 [#review]

**⋯** 메뉴의 **검토**를 고르거나, 홈의 **검토 대기 변경**, 사이드바 개수, 인박스에서 들어갑니다. 변경 요청 상태:

| 상태 | 의미 |
|---|---|
| **검토 대기** | 검토를 기다립니다. |
| **수정 필요** | 검토자가 작성자에게 의견을 남겼습니다. |
| **병합됨** | 변경이 반영되었습니다. |
| **닫힘** | 병합하지 않고 끝났습니다. |

상세 화면에는 위험 수준, 영향받는 페이지 수, 처리하는 주석 수, 에이전트 설명과 변경 설명, 메인라인에 병합할 수 있는지가 표시되고, 아래에 페이지별 변경 비교와 활동이 있습니다.

### 검토 의견 남기기

1. **리뷰 시작**을 누릅니다.
2. 변경 비교에서 줄을 선택하고 **리뷰에 추가**로 의견을 씁니다. 제출 전 의견은 나만 볼 수 있습니다.
3. **리뷰 제출**을 누릅니다(요약은 선택). 변경 요청이 **수정 필요**로 바뀌고 작성자에게 알림이 갑니다.

작성자는 작업 화면에서 **에이전트에게 맡기기**를 눌러 에이전트가 같은 초안을 고치고 의견마다 답하게 한 뒤, **다시 리뷰 요청**으로 변경 요청을 검토 대기로 돌립니다. 관리자가 아닌 멤버는 자신의 변경 요청을 검토할 수 없습니다.

### 병합, 닫기, 되돌리기

- **병합**: 지식 베이스를 만든 사람과 `owner`, `admin`만 병합할 수 있습니다. 충돌이나 검사 오류가 있거나, 에이전트가 수정 중이거나, 수정 필요 상태일 때는 병합할 수 없습니다. 그사이 다른 사람이 같은 페이지를 바꿨다면 Marvis는 단락 단위로 병합하고, 같은 단락을 양쪽에서 바꾼 경우에만 충돌로 봅니다.
- **닫기**: 작성자와 관리자가 닫을 수 있고, 이유를 적을 수 있습니다. 닫힌 변경 요청은 작업 화면에서 **다시 검토 제출**할 수 있습니다.
- **되돌리기**: 관리자는 병합된 변경 요청, **변경 기록**, 페이지 기록에서 **이 변경 되돌리기**를 누를 수 있습니다. 되돌리기는 변경 요청 전체가 대상이며, 반대 방향의 변경 요청을 만들어 병합된 뒤에 반영됩니다. 이후 변경이 같은 내용을 건드렸다면 자동으로 되돌릴 수 없습니다.

**변경 기록**에는 병합된 모든 변경이 나열되고, **페이지 기록**에는 그 페이지의 버전이 나열됩니다. 열면 무엇이 바뀌었는지 볼 수 있습니다.

## 재검토가 필요한 페이지 [#stale]

모든 페이지에는 재검토일이 있습니다. 기한이 지나면 홈의 **재검토가 필요한 페이지**에 나타나고 페이지 트리와 본문에도 표시됩니다. 재검토 목록에서 페이지 하나씩 또는 전부를 에이전트에게 맡길 수 있고, 어느 쪽이든 작업이 만들어집니다.

## 알림 [#notifications]

인박스의 **지식** 분류에 지식 베이스 알림이 모입니다.

- 새 변경 요청이나 되돌리기가 검토를 기다리거나 작성자가 다시 리뷰를 요청하면 관리자나 검토자에게 알림이 갑니다.
- 검토자가 리뷰를 제출하면 작성자에게 알림이 갑니다.

변경 요청이 병합되거나 닫히면 관련된 지난 알림은 자동으로 보관됩니다.

## 태스크와 대화에서 지식 베이스 쓰기 [#agents]

에이전트는 태스크, 대화, 오토파일럿을 실행할 때 워크스페이스에 어떤 지식 베이스가 있는지 알고 페이지를 검색하고 읽을 수 있습니다. 초안과 변경 요청도 제출할 수 있으며, 변경 요청에는 어느 태스크, 대화, 오토파일럿에서 왔는지 표시됩니다. 에이전트는 `marvis kb` 명령으로 지식 베이스를 읽고 쓰며, 권한은 멤버가 화면에서 가진 권한과 같습니다.

에이전트가 답변에서 지식 베이스, 페이지, 변경 요청, 주석을 언급하면 누를 수 있는 카드로 표시됩니다. 누르면 열리기만 하고 아무에게도 알리지 않습니다.

## 지식 베이스 관리 [#manage]

**⋯** 메뉴에서 **지식 베이스 관리**를 고릅니다.

- **원본 자료**: 에이전트가 수록할 파일을 올립니다. 파일 하나당 최대 100 MB입니다. 파일을 골라 에이전트에게 넘기면 수록 작업이 만들어지고, 목록에는 각 파일을 인용하는 페이지가 표시됩니다.
- **내보내기**: **zip 내보내기**를 누르면 페이지마다 frontmatter가 있는 Markdown 파일로 내보내고, 페이지 사이 링크는 상대 경로로 바뀝니다. Obsidian 같은 도구로 바로 열 수 있습니다.
- **지식 베이스 삭제**: 지식 베이스 이름을 입력해 확인합니다. 삭제하면 주석과 검토 대기 변경이 닫히며, 화면에서 복구할 수 없습니다.

## 권한 [#permissions]

지식 베이스의 **관리자**는 만든 사람과 워크스페이스 `owner`, `admin`입니다.

| 작업 | 할 수 있는 사람 |
|---|---|
| 읽기, 검색, 주석, 내보내기, 원본 자료 업로드, 작업 만들기, 리뷰 | 모든 멤버(작업을 만들려면 고른 에이전트의 사용 권한도 필요) |
| 설정, 병합, 되돌리기, 지식 베이스 삭제 | 관리자 |
| 변경 요청 닫기, 주석을 처리 안 함으로 바꾸거나 되돌리기 | 작성자 또는 관리자 |
| 초안 제출, 다시 리뷰 요청 | 초안을 만든 사람 |
| 작업 보기 | 작업을 시작한 사람 |
