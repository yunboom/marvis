ナレッジベースは、タスク・チャット・コード・ドキュメントに散らばったチームの知識をページにまとめます。ページはエージェントが書いて保守し、事実ごとに出典が付きます。メンバーは読んで注釈し、レビューします。変更はレビューとマージを経て初めて反映されます。

<Callout type="info">
メンバーは画面上でページを直接編集できません。内容を変えたいときは注釈を付けるか、[ナレッジベースのジョブ](#jobs)でエージェントに任せます。
</Callout>

## 変更がナレッジベースに入るまで [#flow]

すべての変更は同じ流れをたどります。

1. エージェントが**下書き**でページを追加・編集・移動・削除します。
2. 下書きが提出前チェックを通ったら**レビューに提出**し、変更リクエストを作成します。
3. メンバーがレビューし、メンテナーが**マージ**します。ページが更新され、以前の版はページ履歴に残ります。

マージされるまで、下書きは作成者と権限のある人にしか見えず、正式なページには影響しません。

## ナレッジベースを作成する [#create]

サイドバーで**ナレッジベース**を開きます。ワークスペースにまだない場合は**ナレッジベースを作成**を、すでにある場合は左上のナレッジベース切り替えか **⋯** メニューから作成します。

作成画面の左側は**ナレッジベースビルダー**との会話、右側は設定です。

1. ビルダーが使うランタイムとモデルを選びます。
2. スターターカード（開発、テスト、プロダクト、チーム全体、エージェントチームの記憶、その他）を選ぶか、作りたいナレッジベースを説明します。ビルダーが読者と用途を確認し、右側に反映します。
3. 右側の設定を確認して**作成**をクリックします。

| 設定 | 説明 |
|---|---|
| 名前、説明 | 切り替えとホームに表示されます。 |
| ディレクトリ名 | ナレッジベースの slug。小文字・数字・ハイフンのみで、作成後は変更できません。 |
| 目的 | 読者、扱う範囲・扱わない範囲、主な用途。エージェントはページを書くときに参照します。 |
| Schema | ページの構成と書き方。**デフォルト**は組み込みの Schema で読み取り専用、**カスタム**は自由に書けます。新規作成時は空のカスタムです。 |

**作成を破棄**すると、会話と設定がまとめて削除されます。途中の作成は残るので、あとから続けられます。

作成後のホームには、最初の進め方として「資料を取り込む → レビューで反映 → 読んで注釈 → 定期メンテナンスを設定」が表示されます。

### 設定を変更する

**⋯** メニューの**ナレッジベースを設定**から、ビルダーとの会話を続けるか、目的と Schema を直接編集し、**保存**ですぐに反映します。設定できるのは、ナレッジベースの作成者とワークスペースの `owner`、`admin` です。

## ナレッジベースを見る [#browse]

**ナレッジベース**を開くと、最後に見たナレッジベースに戻ります。左の列は上から次のとおりです。

- **ナレッジベース切り替え**：各ナレッジベースの未対応件数を表示します。
- **⋯ メニュー**：ナレッジベースを作成、ナレッジベースを設定、ナレッジベースの管理、レビュー、変更履歴、リンクをコピー。
- **ホーム**、**ナレッジベースのジョブ**、**関係図**。
- **ページ**：ページツリー。

### ホーム

ホームには説明と、**未対応**の 3 種類の項目が表示されます。

- **レビュー待ちの変更**：レビューを待っている変更リクエスト。
- **注釈**：未対応の注釈。エージェントが報告した抜けも含みます。
- **再確認が必要なページ**：再確認の期限を過ぎたページ。

その下の**最近の更新**に、最近マージされた変更が並びます。レビュー待ちの変更があると、サイドバーの**ナレッジベース**に件数が表示され、クリックするとレビューに直接移動します。

### ページを読む

ページの事実にはそれぞれ番号付きの引用が付き、ホバーすると出典（タスク、チャット、プルリクエスト、コード、ファイル、Web ページ）が表示されます。コードの出典には確認時のバージョンと行番号が表示され、チャットの出典はチャットを始めた本人だけが開けます。ページ末尾の**出典**に一覧があります。

ページ上部には 3 つのパネルの切り替えがあります。

- **このページの注釈**：このページの注釈を見る・追加する。
- **目次**：ページの見出し構成。
- **ページ情報**：次の再確認日、領域、出典の数、このページにリンクしているページ。

**その他**メニューには**ページ履歴**、**このページをエージェントにチェックさせる**、**リンクをコピー**があります。

まだ書かれていないページへのリンクには、その旨が表示されます。ページツリーの位置で **+** をクリックし、**ここにエージェントにページを書かせる**を選んで内容を書くと、ジョブが作成されます。

自分の下書きが今のページを変更している場合、上部のバーで**正式版**と**下書き**を切り替え、**差分を表示**をオンにできます。

### 検索

- ホームの検索ボックスは今のナレッジベースだけを検索し、該当する段落に移動します。
- ナレッジベース内のどこでも <kbd>⌘</kbd> <kbd>Shift</kbd> <kbd>F</kbd>（Windows / Linux は <kbd>Ctrl</kbd> <kbd>Shift</kbd> <kbd>F</kbd>）ですべてのナレッジベースを検索します。
- ページで <kbd>⌘</kbd> <kbd>F</kbd> を押すと、ページ内の文字を検索します。

既定ではキーワード検索のみです。セルフホストのインスタンスで `MARVIS_EMBEDDING_BASE_URL`、`MARVIS_EMBEDDING_API_KEY`、`MARVIS_EMBEDDING_MODEL` をすべて設定し、Postgres に pgvector 拡張がある場合は、意味検索も加わります。OpenAI 互換の `/v1/embeddings` で 1024 次元のベクトルを返すモデルなら使えます。

<Callout type="warning">
意味検索をオンにすると、マージ済みページの本文と検索語が embedding サービスに送信されます。下書きは送信されません。
</Callout>

### 関係図

左の列の**関係図**は、ページ間のリンクからナレッジベース全体を描き、最上位のページごとに色分けします。リンクのないページとまだ書かれていないページは破線で表示されます。ノードをクリックするとページが開きます。

## 注釈 [#annotations]

内容の誤り・不足・古さに気づいたら注釈を付けます。エージェントは作業時にそれを読みます。注釈の範囲は 3 つです。

| 範囲 | 追加方法 |
|---|---|
| 1 文 | ページで文字を選択し、**注釈**をクリックします。エージェントは元の文を確認できます。 |
| 1 ページ | **このページの注釈**を開き、**注釈を追加**をクリックします。 |
| ナレッジベース全体 | ホームで**ナレッジベースの注釈**を開き、**注釈を追加**をクリックします。 |

注釈の状態：

| 状態 | 意味 |
|---|---|
| **未対応** | まだどの変更も対応していません。 |
| **対応中** | 変更リクエストが対応済みで、マージ待ちです。その変更リクエストがクローズされると未対応に戻ります。 |
| **解決済み** | 対応した変更リクエストがマージされました。 |
| **対応しない** | 変更しないと決めました。**戻す**で未対応に戻せます。 |

注釈の作成者、ナレッジベースの作成者、`owner`、`admin` は、注釈を「対応しない」にしたり戻したりできます。

元の文が書き換えられると注釈は新しい文に付いていき、削除されると注釈は当時の原文を残します。

**エージェントに任せる**で注釈を 1 件渡せます。注釈パネルから未対応の注釈をまとめて渡すこともできます。どちらも注釈を処理するジョブが作成されます。

## ナレッジベースのジョブ [#jobs]

ジョブはナレッジベースに書き込む主な方法です。エージェントと会話すると、エージェントが下書きでページを編集し、あなたが確認してレビューに提出します。

左の列で**ナレッジベースのジョブ**を開き、**新しいジョブ**をクリックします。

1. **実行エージェント**を選びます。使用権限があり、ランタイムが利用できるエージェントだけが表示されます。
2. スターターカードを選ぶか、やりたいことを説明します。

| ジョブ | 内容 |
|---|---|
| **資料を取り込む** | タスク・チャット・コード・ファイル・Web ページの知識をページにまとめます。エージェントはまず何を取り込むかを確認します。 |
| **ヘルスチェック** | 古い内容・矛盾・抜けを調べ、結果を注釈として記録します。ページは直接変更しません。 |
| **知識を統合** | 重複・重なっているページを統合します。 |
| **注釈を処理** | 注釈に沿ってページを修正します。 |
| **定期取り込みを作成**、**定期ヘルスチェックを作成** | エージェントがスケジュール実行する[オートパイロット](/autopilots)を作成します。以後はオートパイロットのページで管理します。 |

注釈、**このページをエージェントにチェックさせる**、ページツリーの **+**、元資料、再確認リストからも、内容を引き継いだジョブを直接作成できます。

ジョブ画面の左側は会話で、いつでも要望を追加したり停止したりできます。右側の**下書きの変更**には、追加・編集・移動・削除されたページと**提出前チェック**の結果が表示されます。

- **エラー**は直さないと提出できません。例：ページヘッダーの必須項目がない、事実に出典がない、同じ階層に同名のページがある、未解決の競合がある。
- **警告**は提出を妨げません。例：コードの出典にバージョンがない、まだ書かれていないページへのリンクがある。

チェックの問題は**エージェントに修正させる**で対応します。その間にメインラインで競合する変更があった場合は、**エージェントにメインラインから更新させる**をクリックします。

問題がなければ**レビューに提出**をクリックします。エージェントのターンが終わっている必要があり、提出できるのは下書きの作成者だけです。提出後、下書きは読み取り専用になります。**下書きを破棄**すると変更は破棄され、ジョブは一覧に残ります。

ジョブは開始した本人だけが見て開けます。一覧は実行中・失敗で絞り込めます。不要なジョブはアーカイブでき、削除できるのはアーカイブ済みのジョブだけです。削除すると会話も消え、未提出の下書きは破棄されます。

## レビューとマージ [#review]

**⋯** メニューの**レビュー**、またはホームの**レビュー待ちの変更**、サイドバーの件数、インボックスから開きます。変更リクエストの状態：

| 状態 | 意味 |
|---|---|
| **レビュー待ち** | レビューを待っています。 |
| **修正待ち** | レビュアーが作成者に意見を出しました。 |
| **マージ済み** | 変更が反映されました。 |
| **クローズ** | マージせずに終了しました。 |

詳細画面にはリスクの度合い、影響するページ数、対応する注釈の数、エージェントの説明と変更の説明、メインラインにマージできるかが表示され、その下にページごとの差分とアクティビティがあります。

### レビューで意見を出す

1. **レビューを開始**をクリックします。
2. 差分で行を選択し、**レビューに追加**で意見を書きます。送信前の意見は自分にしか見えません。
3. **レビューを送信**をクリックします（まとめは任意）。変更リクエストは**修正待ち**になり、作成者に通知されます。

作成者はジョブ画面で**エージェントに任せる**を選ぶと、エージェントが同じ下書きを修正して意見ごとに返信します。そのあと**再レビューを依頼**すると、変更リクエストはレビュー待ちに戻ります。メンテナーでないメンバーは、自分の変更リクエストをレビューできません。

### マージ・クローズ・取り消し

- **マージ**：ナレッジベースの作成者と `owner`、`admin` だけがマージできます。競合やチェックエラーがある、エージェントが編集中、修正待ちのいずれかの間はマージできません。その間に他の人が同じページを変更していた場合、Marvis は段落単位でマージし、同じ段落が両方で変更されたときだけ競合になります。
- **クローズ**：作成者とメンテナーがクローズでき、理由も書けます。クローズされた変更リクエストは、ジョブ画面から**レビューに再提出**できます。
- **取り消し**：メンテナーは、マージ済みの変更リクエスト、**変更履歴**、ページ履歴で**この変更を取り消す**をクリックできます。取り消しは変更リクエスト全体が対象で、逆向きの変更リクエストを作成し、マージされると反映されます。後の変更が同じ内容に触れている場合は自動で取り消せません。

**変更履歴**にはマージ済みの変更がすべて並び、**ページ履歴**にはそのページの各版が並びます。開くと変更内容を確認できます。

## 再確認が必要なページ [#stale]

各ページには再確認日があります。期限を過ぎると、ホームの**再確認が必要なページ**に表示され、ページツリーと本文にも印が付きます。再確認リストから 1 ページずつ、またはまとめてエージェントに任せられ、どちらもジョブが作成されます。

## 通知 [#notifications]

インボックスの**ナレッジ**カテゴリにナレッジベースの通知が届きます。

- 新しい変更リクエストや取り消しがレビュー待ちになったとき、または作成者が再レビューを依頼したとき、メンテナーやレビュアーに通知されます。
- レビュアーがレビューを送信すると、作成者に通知されます。

変更リクエストがマージまたはクローズされると、関連する古い通知は自動でアーカイブされます。

## タスクやチャットでナレッジベースを使う [#agents]

タスク・チャット・オートパイロットを実行するとき、エージェントはワークスペースにあるナレッジベースを把握しており、ページを検索して読めます。下書きや変更リクエストを出すこともでき、変更リクエストにはどのタスク・チャット・オートパイロットから来たかが表示されます。エージェントは `marvis kb` コマンドでナレッジベースを読み書きし、権限はメンバーが画面で持つものと同じです。

エージェントが返信でナレッジベース・ページ・変更リクエスト・注釈に触れると、クリックできるカードとして表示されます。クリックしても開くだけで、誰にも通知されません。

## ナレッジベースを管理する [#manage]

**⋯** メニューの**ナレッジベースの管理**を開きます。

- **元資料**：エージェントに取り込ませるファイルをアップロードします。1 ファイル 100 MB まで。ファイルを選んでエージェントに渡すと取り込みジョブが作成されます。一覧には各ファイルを引用しているページが表示されます。
- **エクスポート**：**zip をエクスポート**すると、各ページが frontmatter 付きの Markdown ファイルとして書き出され、ページ間のリンクは相対パスになります。Obsidian などでそのまま開けます。
- **ナレッジベースを削除**：ナレッジベース名を入力して確認します。削除すると注釈とレビュー待ちの変更はクローズされ、画面から復元することはできません。

## 権限 [#permissions]

ナレッジベースの**メンテナー**は、作成者とワークスペースの `owner`、`admin` です。

| 操作 | 実行できる人 |
|---|---|
| 閲覧、検索、注釈、エクスポート、元資料のアップロード、ジョブの作成、レビュー | すべてのメンバー（ジョブの作成には、選んだエージェントの使用権限も必要） |
| 設定、マージ、取り消し、ナレッジベースの削除 | メンテナー |
| 変更リクエストのクローズ、注釈を「対応しない」にする・戻す | 作成者またはメンテナー |
| 下書きの提出、再レビューの依頼 | 下書きの作成者 |
| ジョブの閲覧 | ジョブを開始した人 |
