Marvis Desktop은 macOS, Windows, Linux에서 사용할 수 있습니다. Web 버전과 같은 계정 및 워크스페이스 데이터를 사용하지만 로컬 데몬을 자동으로 관리하고 워크스페이스별 탭을 따로 유지합니다.

## Desktop과 Web

| | Web | Desktop |
| --- | --- | --- |
| 여는 방법 | 브라우저 | 데스크톱 앱 설치 |
| 워크스페이스 탭 | 브라우저 탭 사용 | 워크스페이스별 독립 탭 모음 유지 |
| 데몬 | CLI를 별도로 설치하고 시작 | 로그인 후 앱이 자동으로 시작 |
| 업데이트 | 페이지 새로 고침 | 데스크톱 앱을 통해 업데이트 |

잠시 확인하거나 공용 컴퓨터에서 사용할 때는 Web이 더 편리합니다.

둘 다 동시에 로그인할 수 있습니다. 같은 Marvis 서비스에 연결되어 있으면 표시되는 데이터가 공유됩니다.

## 설치

[Marvis 다운로드 페이지](https://marvis.ai/download)에서 운영체제와 프로세서 아키텍처에 맞는 설치 패키지를 선택합니다.

| 플랫폼 | 설치 패키지 |
| --- | --- |
| macOS | `.dmg` |
| Windows | `.exe` |
| Linux | `.AppImage`, `.deb`, `.rpm` |

설치 후 [Desktop을 Marvis 서버에 연결](#서버-연결)하고 로그인합니다. 로그인하면 Desktop이 내장 Marvis CLI를 시작하고 로컬에 설치된 AI 코딩 도구를 감지합니다.

<Callout type="info">
Desktop 내장 CLI는 앱이 런타임을 관리할 때만 사용합니다. 터미널에서 `marvis issue` 같은 명령도 실행하려면 [빠른 시작 2단계](/cloud-quickstart#2-컴퓨터-연결)에 따라 CLI를 별도로 설치하세요.
</Callout>

## 데스크톱 탭

Desktop은 워크스페이스마다 탭을 따로 저장합니다. 예를 들어 워크스페이스 A에서 태스크 세 개를 연 뒤 워크스페이스 B로 전환하면 B의 탭이 표시됩니다. A로 돌아오면 이전 세 탭이 그대로 남아 있습니다.

같은 리소스는 현재 워크스페이스에서 한 번만 열립니다. 탭은 순서를 바꾸고, 고정하고, 닫을 수 있으며 각각의 앞으로 가기, 뒤로 가기, 스크롤 위치도 유지됩니다. 현재 배포 환경의 앱 링크를 클릭하거나 붙여 넣으면 브라우저로 이동하지 않고 탭에서 바로 열립니다.

로그아웃하면 로컬에 저장된 모든 탭이 삭제되어 다음 로그인 사용자가 이전 계정의 페이지를 보지 못합니다.

## 내장 데몬

로그인하면 Desktop이 현재 Marvis 서비스 전용 CLI profile을 만들고 이 profile로 데몬을 시작합니다. profile은 다음 위치에 있습니다.

```text
~/.marvis/profiles/desktop-<host>/
```

터미널에서 사용하는 기본 profile을 읽거나 덮어쓰지 않습니다. 다른 데몬을 직접 동시에 시작하면 Marvis에는 각각 별도 런타임으로 표시됩니다.

Desktop 설정에서 실행 상태와 로그를 확인할 수 있습니다. 도구가 감지되지 않으면 먼저 일반 터미널에서 실행되고 로그인되어 있는지 확인한 뒤 Desktop 데몬을 다시 시작하세요.

## Desktop 업데이트

자동 업데이트는 기본으로 켜져 있습니다. 앱이 백그라운드에서 새 버전을 확인하고 다운로드합니다. 다운로드가 끝나면 즉시 다시 시작해 설치하거나 다음 종료 시 설치할 수 있습니다. **설정 → 업데이트**에서 자동 확인을 끄거나 새 버전을 직접 확인할 수도 있습니다.

업데이트는 운영체제와 프로세서 아키텍처에 따라 배포됩니다.

- Windows arm64와 macOS x64(Intel)는 각각 별도 업데이트 소스를 사용합니다.
- 나머지 아키텍처는 기본 업데이트 소스를 사용합니다.
- 앱이 업데이트 소스를 자동으로 맞추므로 직접 선택할 필요가 없습니다.
- Linux 자동 업데이트는 `.AppImage`에서만 작동합니다. `.deb`와 `.rpm`은 새 설치 패키지를 내려받아 덮어씁니다.
- 자동 업데이트에 실패해도 다운로드 페이지에서 해당 설치 패키지를 받아 덮어쓸 수 있습니다.

## 서버 연결

Desktop은 Marvis 서버, 즉 backend에만 연결합니다. Web 앱은 선택 사항입니다.

### 처음 실행

서버가 설정되어 있지 않으면 Desktop에 **Marvis 서버에 연결** 화면이 나타납니다.

1. **로컬 네트워크의 서버**에서 서버를 고르거나 주소를 입력합니다. 기본 주소는 `http://marvis.local:13840`입니다.
2. 주소를 입력했다면 **연결 테스트**를 클릭합니다. Desktop이 서버 이름과 버전, 또는 연결할 수 없는 이유를 표시합니다.
3. **계속**을 클릭하고 확인 페이지에서 주소를 확인한 뒤 **연결**을 클릭합니다.
4. 로그인합니다.

서버가 나타나거나 사라지면 목록이 갱신됩니다. **다시 검색**을 클릭하면 네트워크를 다시 검색합니다. 컴퓨터와 서버는 같은 네트워크에 있어야 합니다. 이 컴퓨터에서 실행 중인 서버에는 **이 컴퓨터** 표시가 붙습니다. 버전이 너무 오래된 서버는 목록에 표시되지만 선택할 수 없습니다.

Desktop은 확인하기 전에는 연결하지 않으며 자동으로 로그인하지도 않습니다. HTTP를 쓰는 서버는 암호화되지 않으며, 확인 페이지에 이 사실이 표시됩니다.

선택한 서버는 Desktop의 앱 데이터 폴더에 `server.json`으로 저장됩니다.

| 플랫폼 | 경로 |
| --- | --- |
| macOS | `~/Library/Application Support/Marvis/` |
| Linux | `~/.config/Marvis/` |
| Windows | `%APPDATA%\Marvis\` |

### 서버 전환

**설정 → 이 기기 → 서버**를 엽니다. 이 페이지에는 다음이 표시됩니다.

- 현재 서버의 이름, 주소, 연결 상태.
- 로컬 네트워크에서 찾은 다른 서버. 각 서버에 **전환** 버튼이 있습니다.
- **다른 주소** 입력란. **연결 테스트**와 **전환** 버튼이 있습니다.

전환하면 현재 계정에서 로그아웃됩니다. Desktop이 확인을 요청한 뒤 새 서버를 저장하고 로그인 페이지를 엽니다. 내장 데몬은 새 서버의 프로필을 자동으로 사용합니다.

이 설정은 이 컴퓨터에만 적용됩니다.

### 연결이 끊어졌을 때

- 서버가 응답하지 않으면 주 영역 상단에 배너가 나타나 연결이 끊어졌고 다시 연결하는 중임을 알립니다.
- 실패가 이어지면 배너가 서버에 연결할 수 없음을 알리고 **다시 시도**와 **서버 전환** 버튼이 나타납니다. Desktop은 계속 확인하며 서버가 돌아오면 자동으로 다시 온라인이 됩니다.
- 로컬 네트워크 목록에서 고른 서버는 IP 주소로 저장됩니다. 이 주소가 응답하지 않고 같은 서버(인스턴스 ID로 식별)가 로컬 네트워크에 새 IP로 나타나면 Desktop이 새 주소로 바꾸고 다시 연결했음을 알립니다.
- 저장된 주소에서 다른 서버가 응답하면 Desktop이 **이 주소에 다른 서버가 있습니다**를 표시하고 자동으로 전환하지 않습니다. **계속 기다리기** 또는 **서버 전환**을 선택합니다.

### Web 앱이 없는 경우

서버에 Web 주소가 없거나 그 주소가 `localhost`이면 Desktop은 Web 앱이 없는 것으로 처리합니다.

- 로그인 페이지에는 이메일 코드 로그인만 남고 Google과 Feishu 버튼은 숨겨집니다.
- **링크 복사**는 `marvis://open?...` 링크를 만듭니다. Desktop이 설치되어 있고 같은 서버에 연결된 컴퓨터에서는 이 링크가 Desktop에서 열립니다.

## desktop.json으로 서버 미리 설정

운영자는 컴퓨터별로 서버를 미리 설정할 수 있습니다. Desktop은 앱에서 선택한 서버가 없을 때만 이 설정을 읽습니다. 연결 페이지를 표시하지 않고 바로 연결하며 이 파일에는 쓰지 않습니다.

사용자 디렉터리의 `.marvis` 안에 `desktop.json`을 만듭니다.

| 플랫폼 | 경로 |
| --- | --- |
| macOS | `/Users/<사용자>/.marvis/desktop.json` |
| Linux | `/home/<사용자>/.marvis/desktop.json` |
| Windows | `C:\Users\<사용자>\.marvis\desktop.json` |

위 경로는 기본 위치입니다. 홈 디렉터리를 옮겼거나 리디렉션한 경우에는 실제 경로를 사용하세요.

```json
{
  "schemaVersion": 1,
  "apiUrl": "https://api.example.com"
}
```

<Callout type="warning">
이 파일은 CLI의 `~/.marvis/config.json`과 **다른 파일**이며 키 이름도 다릅니다. CLI는 `server_url`을, Desktop은 `apiUrl`을 사용합니다. Desktop은 CLI 설정을 읽지 않고 `~/.marvis/profiles/desktop-<host>/` 아래에 별도의 daemon 프로필을 관리합니다. `config.json`을 수정해도 Desktop이 연결하는 서버는 바뀌지 않습니다.
</Callout>

`apiUrl`은 backend의 공개 주소로 필수이며 `http` 또는 `https`를 사용해야 합니다. 다음 두 주소는 생략할 수 있으며 Desktop이 자동으로 추론합니다.

- `wsUrl`: `apiUrl`의 프로토콜을 `ws` 또는 `wss`로 바꾸고 경로 뒤에 `/ws`를 추가합니다.
- `appUrl`: 도메인이 `api.`로 시작하고 세 구간 이상이면 `api.` 접두사를 제거합니다(`api.example.com` → `example.com`). 그렇지 않으면 `apiUrl`과 동일하게 유지합니다.

미리 설정한 구성에는 항상 Web 주소가 있으며, `appUrl`을 생략하면 Desktop이 추론합니다. Web 앱 없이 Desktop을 사용하려면 앱에서 서버를 선택합니다.

보통 `apiUrl`만 작성하면 됩니다. 추론 결과가 맞지 않을 때 명시적으로 덮어쓰면 됩니다. 일반적인 경우는 세 가지입니다.

- Web과 API가 서로 다른 도메인을 사용
- WebSocket을 별도로 배포
- 도메인이 접두사 제거 규칙을 만족하지 않음(`api.local` 같은 두 구간 도메인은 접두사를 제거하지 않음)

```json
{
  "schemaVersion": 1,
  "apiUrl": "https://api.example.com",
  "appUrl": "https://app.example.com",
  "wsUrl": "wss://ws.example.com/socket"
}
```

저장한 뒤 Desktop을 다시 시작합니다. 이 설정은 시작할 때 한 번만 읽습니다. 두 가지 실패는 다르게 나타나므로 이를 보고 빠르게 구분할 수 있습니다.

- **파일을 찾지 못한 경우**(디렉터리가 다르거나 파일 이름이 `desktop.json`이 아닌 경우): Desktop은 연결 페이지를 표시하고 오류는 표시하지 않습니다. 따라서 Desktop이 계속 서버 연결을 요구하고 설정 오류도 없다면, 파일이 Desktop이 찾는 위치에 없다는 뜻입니다.
- **파일은 찾았지만 유효하지 않은 경우**(JSON, 버전, URL에 문제가 있는 경우): Desktop에 설정 오류가 표시됩니다.

해당 파일을 삭제하고 다시 시작하면 연결 페이지로 돌아갑니다. 앱에서 서버를 선택한 적이 있다면 앱 데이터 폴더의 `server.json`도 삭제합니다.

<Callout type="warning">
Desktop은 브라우저와 실행 컴퓨터에서 모두 접근할 수 있는 주소에만 연결할 수 있습니다. 원격 자체 호스팅 인스턴스에 HTTPS가 없거나 WebSocket 프록시가 설정되지 않으면 Desktop이 연결되지 않습니다. 전체 설정은 [자체 호스팅 빠른 시작](/self-host-quickstart#3-접근-방식-선택)을 참고하세요.
</Callout>

### Windows: 파일 이름과 인코딩 확인

Windows에서는 편집기의 두 가지 기본 동작 때문에 Desktop이 사용할 수 없는 파일이 조용히 만들어집니다.

- **메모장이 `.txt`를 덧붙입니다.** `desktop.json`으로 저장해도 실제로는 `desktop.json.txt`가 될 수 있으며, Desktop은 이를 파일이 없는 것으로 처리합니다. 파일 탐색기에서 파일 확장명 표시를 켜거나 저장 대화 상자에서 *모든 파일*을 선택하세요. 실제 파일 이름을 확인하려면 PowerShell에서 `Get-ChildItem "$env:USERPROFILE\.marvis" -Filter "desktop.json*"`를 실행하세요. `Name` 열이 정확히 `desktop.json`이어야 합니다.
- **PowerShell 리디렉션은 UTF-16이나 BOM을 씁니다.** `> desktop.json`과 `Out-File`은 파싱할 수 없는 인코딩을 만들 수 있으며, 설정 오류로 나타납니다.

두 가지를 모두 피하려면 PowerShell에서 한 번에 파일을 만듭니다.

```powershell
$dir = "$env:USERPROFILE\.marvis"
New-Item -ItemType Directory -Force $dir | Out-Null
$json = @'
{
  "schemaVersion": 1,
  "apiUrl": "https://api.example.com"
}
'@
[System.IO.File]::WriteAllText("$dir\desktop.json", $json)
```

## Windows Defender가 Marvis를 바이러스로 탐지하는 경우

**증상**: Windows 보안이 `Trojan:Script/Wacatac.B!ml` 같은 위협을 보고하고 Desktop 설치 경로 안의 파일을 격리합니다. 격리되는 대상은 보통 앱 실행 파일이 아니라 함께 포함된 CLI입니다.

```text
C:\Users\<사용자>\AppData\Local\Programs\@marvisdesktop\resources\app.asar.unpacked\resources\bin\marvis.exe
```

**오탐입니다.** `!ml` 접미사는 이 판정이 악성코드 시그니처 일치가 아니라 Defender의 머신러닝 휴리스틱에서 나왔다는 뜻입니다. Marvis의 Windows 빌드는 아직 Authenticode 코드 서명을 하지 않았고, 갓 배포된 서명 없는 바이너리가 백그라운드 프로세스를 띄우고 네트워크 연결을 여는 형태는 이런 휴리스틱이 가장 의심스럽게 평가하는 프로필입니다. 모든 Windows 산출물은 이 저장소의 공개 소스에서 GitHub Actions로 빌드됩니다.

**직접 검증할 수 있습니다** — 모든 GitHub 릴리스에는 CLI 아카이브 전체를 포함한 `checksums.txt`가 함께 게시됩니다.

```powershell
Get-FileHash .\marvis-cli-<version>-windows-amd64.zip -Algorithm SHA256
```

출력된 해시를 [최신 릴리스](https://github.com/yunboom/marvis/releases/latest)의 `checksums.txt` 해당 줄과 비교하세요.

**해결 방법**:

1. **격리된 파일 복원** — Windows 보안 → *바이러스 및 위협 방지* → *보호 기록* → Marvis 항목 선택 → *작업* → *복원*.
2. **제외 항목 추가** (다시 격리되지 않도록) — *바이러스 및 위협 방지* → *설정 관리* → *제외* → *제외 추가 또는 제거* → *폴더*에서 다음 두 경로를 모두 추가합니다.
   - `%LOCALAPPDATA%\Programs\@marvisdesktop`
   - `%APPDATA%\Marvis`

   두 경로 모두 필요합니다. 포함된 CLI가 사라지면 Desktop이 대체 바이너리를 `%APPDATA%\Marvis\bin`에 내려받기 때문에, 설치 폴더만 제외하면 새로 받은 파일이 다시 격리되는 상황이 반복됩니다.
3. **오탐을 Microsoft에 신고** — [Microsoft Security Intelligence 파일 제출 페이지](https://www.microsoft.com/en-us/wdsi/filesubmission)에서 *Software developer*와 *Incorrectly detected as malware*를 선택하세요. 모든 사용자에 대해 탐지를 철회시키는 방법은 이것이며, 보통 며칠 안에 반영됩니다.

<Callout type="warning">
이 제외 항목은 [다운로드 페이지](https://marvis.ai/download) 또는 [GitHub 릴리스](https://github.com/yunboom/marvis/releases)에서 설치했고 체크섬이 일치하는 경우에만 추가하세요. 제외를 설정하면 해당 폴더 안의 모든 파일에 대해 실시간 보호가 꺼집니다.
</Callout>
