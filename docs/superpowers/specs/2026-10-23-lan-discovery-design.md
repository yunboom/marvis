# 局域网自动发现服务端：设计

日期：2026-10-23
状态：待确认
设计稿：Marvis 设计稿画布 20–23 号画板（https://claude.ai/artifact/8JtMci5WWr68cixGLKptzZ）

## 背景与目的

团队在办公室一台 Mac 上跑 Marvis 服务端，同事在同一个 Wi-Fi 下用桌面端和命令行连接。这是“部署着玩”的场景，不追求正式运维。

现在客户端要靠人告诉它服务器地址：

- 桌面端正式包先读每台电脑上的 `~/.marvis/desktop.json`，没有就连代码里内置的 `https://api.marvis.ai`。这个地址是品牌替换时从上游 `api.multica.ai` 改来的，域名并不存在，所以新装的桌面端打开就连不上。要连自己的服务器，只能在每台电脑上手写这个文件。
- 命令行要执行 `marvis setup self-host --server-url ... --app-url ...`，地址和端口都得问人。

目的：同事装好桌面端或命令行后，不问人、不记 IP，就能连上局域网里的 Marvis。

## 目标

1. 服务端在局域网里广播自己；桌面端和命令行列出局域网里的 Marvis，确认后连接。
2. 桌面端只需要连服务端（后端），网页端可选；部署了网页端时，浏览器用户可用 `http://marvis.local:3000` 访问。
3. 桌面端首次启动出现“连接服务器”页；设置里能查看当前服务器、切换服务器。
4. 命令行 `marvis setup self-host` 不带参数时自动发现，默认推荐桌面端正在用的服务器。
5. 所有入口都有地址输入框，预填 `http://marvis.local:13840`，带“测试连接”。
6. 服务器掉线、IP 变化时，客户端给出明确状态并尽量自动恢复。

## 非目标

- Docker 部署下的广播（Docker Desktop for Mac 的容器发不出局域网广播，已在本机实测确认）。Docker 部署的服务器仍可通过手动输入地址连接。
- 跨网段、跨 VLAN 的发现。
- 移动端。
- 服务端的设置界面（服务端只用 `.env`）。
- 正式的安装脚本、开机自启、运维文档。

## 反目标（做到了也算失败）

- 客户端发现后自动连上、自动登录，不经用户确认。
- 客户端修改服务端的任何东西；客户端只决定“这台电脑连哪台服务器”。
- 桌面端读写终端命令行的默认配置 `~/.marvis/config.json`（违反 #6399 的约定）。
- 地址上换了一台服务器时，客户端悄悄连过去。
- 发现失败时用户无路可走（必须始终有地址输入框）。

## 已和用户确认的决定

- **部署**：服务端在 Mac 上不用 Docker，直接用源码运行（`make start` 这类方式），由后端进程自己广播。不做安装脚本和开机自启。
- **发现机制**：mDNS / DNS-SD 广播，服务类型 `_marvis._tcp`。
- **端口**：广播后端实际监听的端口。后端默认端口已从 8080 改为 13840（见 CLAUDE.md 决策四），不新增端口配置。
- **网页端可选**：桌面端只连服务端，不依赖网页端；网页端部署与否由运维决定。
- **地址输入**：预填默认地址，旁边“测试连接”，结果就地显示；测试通过才允许继续或切换。
- **网页端**：不做发现；部署了网页端时，用广播的主机名 `marvis.local` 加网页端口访问。
- **命令行和桌面端**：默认推荐，不自动同步。桌面端自带的守护进程本来就跟着桌面端走（`profiles/desktop-<host>`），不改；终端里手敲的 `marvis` 保持独立，只在 `setup self-host` 时把桌面端正在用的服务器排第一、默认选中。
- **客户端数据位置**：用户在界面上选的服务器存进桌面应用的数据目录，不写 `~/.marvis/desktop.json`。
- **命名**：机器级标识统一用 marvis（`~/.marvis`、`marvis://`、`Marvis.app`），不再规避腾讯 Marvis。
- **服务器名称与主机名**：只有服务器名称可配置；主机名固定为 `marvis`，不提供配置项。
- **界面**：以设计稿 20（连接服务器）、21（设置 · 服务器）、22（命令行选择服务器）、23（服务器离线）为准。

## 方案

### 1. 服务端广播

后端进程启动时开始广播，退出时撤销：

- **服务**：DNS-SD 实例名为服务器名称，类型 `_marvis._tcp`，端口为后端实际监听的端口（默认 13840）。TXT 记录：
  - `v=1`：发现协议版本；
  - `name=<服务器名称>`；
  - `ver=<服务端版本>`；
  - `id=<实例 ID>`：稳定的随机 ID，用于客户端认出“还是不是那台服务器”。
- **主机名**：同时广播主机名 `marvis.local`，指向本机局域网 IP，供浏览器访问和作为输入框默认地址。主机名固定，不提供配置。网段里已有同名主机（另一台 Marvis）时，按 mDNS 冲突规则自动改名为 `marvis-2.local`，并在日志里写明实际使用的名字。服务器名称给人看（可含中文、空格），主机名给机器用（只能是字母数字），两者分开。
- **服务器地址**：桌面端和命令行只用后端地址 `http://<主机名>.local:<后端端口>`。
- **网页地址（可选）**：`/api/config` 已有的 `daemon_app_url` 在服务端配置了网页地址时返回它；客户端只在它不是回环地址（localhost / 127.0.0.1 / ::1）时采用，否则视为没有网页端。
- **配置**（都写在服务器的 `.env` 里，全部可选，不配也能用）：
  - `MARVIS_LAN_DISCOVERY`：设为 `false` 时不广播，默认广播；
  - `MARVIS_LAN_NAME`：服务器名称，默认取电脑名。
- **核实接口**：匿名可访问的 `GET /api/config` 增加 `server_name`、`instance_id` 两个字段（已有 `server_version`）。客户端用它核实“这是 Marvis、是哪一台、什么版本”，手动输入地址时也靠它测试连接。

### 2. 网页访问与登录来源

部署了网页端时，同事可能用 `marvis.local:3000` 或局域网 IP 打开网页。登录相关的来源校验（CORS、WebSocket 来源、Cookie）规则改为：**只信任从本服务器自己的地址打开的页面**，即请求来源和请求到达的地址一致（网页与接口同源）。

- 不需要维护允许列表，也不需要部署的人改 `.env`；
- 多台服务器互不影响，A 服务器不会信任 B 服务器打开的页面；
- 现有的 `FRONTEND_ORIGIN` 等配置继续有效，规则只在其基础上放行同源请求；
- 飞书、Google 登录的回调地址仍需在对应平台登记 `http://marvis.local:3000/auth/callback`。

### 3. 桌面端

- **首次启动**：正式包没有任何服务器配置时（应用数据目录里没有已选服务器，也没有 `~/.marvis/desktop.json`），显示“连接服务器”页（设计稿 20）。删掉不存在的内置地址 `api.marvis.ai`。开发模式仍走 `VITE_*` 环境变量。
- **发现**：在 Electron 主进程浏览 `_marvis._tcp`（渲染进程没有组播能力），通过 IPC 推给渲染进程；列表实时增减，提供“重新查找”。
- **核实**：主进程请求候选服务器的 `/api/config`，拿到名称、版本、实例 ID；版本不满足的显示但不可选；本机运行的服务器标“本机”。
- **地址输入**：预填 `http://marvis.local:13840`；“测试连接”同样走 `/api/config`，结果四种：可以连接（显示名称和版本）、无法连接、不是 Marvis 服务器、版本过旧。
- **确认**：选中后进入确认页，展示地址、版本、主机名；HTTP 连接时提示不加密。确认后保存，重新加载进入登录页。
- **保存位置**：已选服务器存进应用数据目录（macOS 为 `~/Library/Application Support/Marvis/`，与窗口位置等数据放在一起），内容包括地址、名称、实例 ID、来源（发现或手动）。`~/.marvis/desktop.json` 继续读取，但只在应用数据目录里没有已选服务器时作为初始值，界面不写它。
- **没有网页端时**：运行时配置的 `appUrl` 可为空。为空时隐藏依赖网页端的入口：登录页的 Google、飞书按钮（只保留邮箱验证码登录），以及“复制链接”“在浏览器中打开”。有网页地址时行为与现在一致。
- **设置 · 服务器**（设计稿 21）：放在设置“本设备”分组首位，任何人都能改，只影响这台电脑。一页内完成：
  - 顶部当前服务器卡片，显示名称、地址、连接状态；
  - 中间是局域网里找到的其他服务器，各带“切换”；
  - 底部“其他地址”输入框，加“测试连接”和“切换”；
  - 切换前弹窗确认“会退出当前账号”，确认后退出登录、保存、进入登录页。
  - 守护进程按新地址自动换成对应的 `desktop-<host>` 配置，现有逻辑不变。
- **掉线与恢复**（设计稿 23）：
  - 连接断开时，主区顶部显示“正在重新连接”，页面内容变淡但可读；
  - 多次失败后变为“无法连接”，提供“重试”和“切换服务器”；
  - 同时继续监听广播：同一实例 ID 出现在新 IP 时，自动改用新地址并提示；
  - 保存的地址上回应的是另一个实例 ID 时，弹窗提示“这个地址上换了一台服务器”，不自动切换。

### 4. 命令行

- `marvis setup self-host` 在交互式终端里、且没传 `--server-url` 时（设计稿 22）：
  1. 读桌面端应用数据目录里的已选服务器（只读，路径用 Go 的 `os.UserConfigDir()` 拼上 `Marvis`，与 Electron 的应用数据目录一致）；如果有，显示“桌面端正在使用：X”。
  2. 用 mDNS 查找约 3 秒，列出结果；桌面端正在用的那台排第一、默认选中，标“桌面端正在使用”。
  3. 最后一项“手动输入地址”，默认值 `http://marvis.local:13840`，回车后先测试连接。
  4. 选定后走现有的 self-host 配置和浏览器登录流程，接口地址与网页地址相同。
- 服务端没有网页地址时，不走浏览器登录，提示用 `marvis login --token` 登录（Token 在桌面端“设置 → API Token”创建）。
- 非交互（脚本、CI）或传了 `--server-url` 时，行为与现在完全一致。
- 终端命令行永不写入桌面端的数据；桌面端也永不读写终端命令行的默认配置。

### 5. 顺带修正

- 桌面端文档（`apps/docs/content/docs/desktop-app*.mdx`）补充“连接服务器”页的说明。
- 自托管文档补一段：Docker 部署不支持局域网发现，需要发现时用源码方式运行服务端。

### 6. 安全

- 发现结果只是候选，必须经 `/api/config` 核实、由用户确认才连接，任何阶段都不自动登录、不发送凭证。
- 确认页展示完整地址和主机名，HTTP 时明确提示不加密。
- 客户端按实例 ID 识别服务器，地址相同但实例 ID 变化时不自动连接。

## 补充：桌面端飞书登录不依赖网页端（2026-10-23 追加）

只部署服务端时，桌面端仍显示“使用飞书登录”，由后端直接完成飞书授权回调。

- **飞书后台**：重定向 URL 已登记 `http://marvis.local:13840/auth/lark/desktop-callback`（用户已配置）。
- **后端新增两个浏览器访问的地址**（走登录限流）：
  - `GET /auth/lark/desktop-start?nonce=<桌面端生成的一次性随机串>`：校验 nonce 格式，生成一次性 `state`（有效 10 分钟，只能用一次，存在后端内存里，单实例部署），跳转到飞书授权页（`client_id`、`redirect_uri`、`state`、`scope=contact:user.email:readonly`，与网页端一致）。
  - `GET /auth/lark/desktop-callback?code&state`：校验并作废 `state`；用户取消或出错时显示简短的错误页；成功时沿用现有飞书登录的换码、取用户信息、租户白名单、邮箱、找人或建号逻辑，签发登录凭证，然后跳回 `marvis://auth/callback?token=<凭证>&nonce=<nonce>`。跳转页同时给一个“打开 Marvis”按钮，防止浏览器拦截自定义协议跳转。
- **回调地址的确定**：环境变量 `MARVIS_LARK_LOGIN_DESKTOP_REDIRECT_URI` 优先；未配置且局域网发现开启时，用实际广播的主机名和后端端口拼出 `http://<主机名>.local:<端口>/auth/lark/desktop-callback`；都没有时桌面端不显示飞书按钮。
- **`/api/config`** 新增 `lark_desktop_login`（布尔）：飞书登录已配置且回调地址可用时为 true。
- **桌面端**：
  - 有网页端时沿用现有流程；没有网页端且 `lark_desktop_login` 为 true 时，飞书按钮改走新流程：主进程生成 nonce（10 分钟有效），用浏览器打开 `<服务器地址>/auth/lark/desktop-start?nonce=…`。
  - 深链 `marvis://auth/callback` 带 `nonce` 时，只有与待完成的 nonce 一致才接受凭证，用后作废；不带 `nonce` 的旧网页端跳转流程保持不变。
- **Google 登录**：Google 不允许局域网地址作为回调，没有网页端时仍隐藏。
- **错误页文案**（中文，简短）：标题“飞书登录失败”，正文按原因给出“登录已过期，请回到 Marvis 重新点击飞书登录”“这个飞书企业不允许登录”“飞书账号没有邮箱”“服务器未配置飞书登录”；用户在飞书页取消时显示“已取消飞书登录”。
