# 飞书邀请：设计

日期：2026-10-23
状态：待确认
设计稿：Marvis 设计稿画布 30–34 号画板（https://claude.ai/artifact/8JtMci5WWr68cixGLKptzZ）
讨论页：https://claude.ai/artifact/Vgk8bmNwiNo6cpu9T1gTq4（参数表、ID 识别规则、错误码的完整版本）

## 背景与目的

Marvis 部署在办公室局域网里，同事都用飞书登录。邀请成员现在只能发邮件，服务端没配邮件服务时邮件根本发不出去，验证码和邀请链接只打印在服务端日志里。另外，没有网页端时分享链接在桌面端被隐藏，界面上只剩邮件邀请。

加入流程本身是通的：管理员建好邀请后，同事用飞书登录，系统按邮箱匹配，侧栏就会出现这条邀请。缺的是“通知”，同事不知道自己被邀请了。

目的：管理员或智能体把一张邀请卡片发到飞书群或某个人，点“加入工作区”的人直接成为成员，不点的人不受影响。

## 目标

1. 管理员在 Marvis 成员页把邀请卡片发到一个或多个飞书群，或发给一个或多个人。
2. 智能体通过 CLI 做同样的事：发卡片、查看、撤销。
3. 群里或私聊里的人点卡片上的“加入工作区”，服务端直接把他加为成员，不需要再到 Marvis 里接受。
4. 管理员能看到每张卡片发给了谁、谁已加入、何时过期，能单独撤销；撤销后飞书里的卡片同步变成失效状态。
5. 飞书登录的成员显示飞书头像，重新飞书登录时更新为最新的飞书头像。

## 非目标

- 不做按姓名搜飞书同事。飞书按姓名搜人要用户身份令牌，应用身份查不了；个人邀请用邮箱。
- 不做“同组织直接加入”和“链接预览成卡片”。
- 不替换邮件邀请。邮件邀请和分享链接保持原样，配了邮件服务的照常可用。
- 智能体不用自己的飞书机器人发卡片。
- 不做后台头像刷新，头像只在飞书登录时更新。
- 不限制能发卡片的群：工作区管理员可以选 Marvis 机器人所在的任何群。

## 反目标（做到了也算失败）

- 群里没点卡片的人被加进了工作区。
- 私聊卡片被别人点了也能加入。
- 群里任何人都能借智能体拉人进工作区，绕过管理员权限。
- 撤销后卡片还能用，或者过期的卡片看起来仍然有效。
- 飞书头像同步覆盖了用户在 Marvis 里自己上传的头像。

## 已和用户确认的决定

- 采用“飞书卡片 + 点击即加入”，不输入邮箱就能发到群里；没点的人不加。
- 卡片可以发到群，也可以发给个人。
- 要有 CLI，智能体用它发。CLI 不提供“列出群”的命令，群 ID、同事的 open_id 由智能体用飞书 CLI 去查。
- CLI 命令为 `marvis workspace lark-invite send / list / get / revoke`。接收方参数和飞书 CLI 的 `im +messages-send` 保持一致：`--chat-id oc_xxx` 或 `--user-id ou_xxx`，二选一，一次一个接收方。详见第 9 节。
- 头像遵循画布 24 号改版规范；飞书登录的成员显示飞书头像。飞书换了头像，重新飞书登录时 Marvis 跟着更新，不做后台刷新。
- 发卡片的群不限制范围：任何工作区的管理员都能选 Marvis 机器人所在的全部群，也能按邮箱查飞书同事的姓名和部门。

## 我做的判断（请在阅读时确认）

- **发卡片的机器人**：统一用飞书登录那个自建应用的机器人，名称显示为 Marvis。原因是智能体的机器人是扫码创建的飞书“个人智能体”应用，权限由飞书预设，能不能接收卡片点击没法保证。代价是 Marvis 机器人要先被拉进目标群。
- **智能体代发要两个人都是管理员**：智能体所属的账号（运行时所有者）和触发这次任务的人，都必须是工作区管理员或所有者。只看前者，群里任何人都能借智能体拉人；只看后者，要另写一套路由权限。两者都要求，最安全，也能直接放进现有的管理员路由组。
- **服务端开关**：新增 `MARVIS_LARK_INVITE_ENABLED`，默认关闭。只有打开的服务端才起长连接、才能发卡片。原因是同一个飞书应用常被多个部署共用（正式服务端、开发机的 `.env`），飞书会把一次点击随机推给其中任意一条连接，推到开发机上这次点击就丢了。- **每个接收方一张卡片、一条邀请记录**：一次发给 3 个群就是 3 条记录，可单独撤销。
- **默认值**：有效期 7 天，可选 1 小时到 30 天；群卡片人数默认不限；个人卡片固定 1 次。
- **界面里的个人邀请用邮箱添加**，飞书里查不到的邮箱标红，发送时跳过。
- **头像同步**：每次飞书登录都用飞书头像覆盖，但用户在 Marvis 里手动上传过头像、或选了表情头像的不覆盖。
- **过期卡片**：不为改卡片单独跑定时任务。有人点过期卡片时，回提示并把卡片改成失效状态；管理员撤销时立即改卡片。
- **群头像**：Marvis 界面里群按小队样式画（白底细描边、圆角方形），群有自定义头像时显示图片。

## 方案

### 1. 飞书开放平台配置

复用飞书登录用的自建应用（`MARVIS_LARK_LOGIN_APP_ID` / `MARVIS_LARK_LOGIN_APP_SECRET`），不新增应用。新增一个开关 `MARVIS_LARK_INVITE_ENABLED`（默认关闭），只在正式服务端打开，见“我做的判断”。飞书开放平台上要做的配置：

- 开启机器人能力，机器人名称和头像用 Marvis。
- 新增权限：
  - `im:message:send_as_bot`：发卡片、更新卡片。
  - `im:chat:readonly`：列出机器人所在的群，供界面选择。
  - `contact:user.id:readonly`：界面按邮箱换 open_id。
  - `contact:user.base:readonly`：点击人和接收人的姓名、头像。
  - `contact:user.email:readonly`：点击人的邮箱，用来找到或建立 Marvis 账号。
- 事件与回调：连接方式选长连接，在“回调配置”里添加 `card.action.trigger`。
- 可用范围覆盖要邀请的人，然后发布新版本。

服务端没配登录应用、或没打开开关时，飞书邀请整体不可用：接口返回 `lark_not_configured`，成员页显示“服务器未配置飞书机器人”。飞书邀请的长连接只依赖登录应用的凭据，不依赖智能体机器人用的 `MARVIS_LARK_SECRET_KEY`。配了应用但没开机器人或缺权限时，发送会失败，失败原因按飞书返回的错误码映射成第 9 节的错误码。

### 2. 数据模型

现有的分享链接每个工作区只能有一条有效记录（创建新链接会停用旧的），不能直接复用。新增两张表：

`lark_invite`：一张卡片一行。

| 字段 | 说明 |
|---|---|
| `id` | 主键，也写进卡片按钮的回传值 |
| `workspace_id` | 工作区 |
| `target_type` | `chat` 或 `user` |
| `target_id` / `target_id_type` | 调用方给的 ID 和类型：`chat_id`、`open_id`（CLI）、`email`（界面） |
| `target_open_id` | 个人卡片在发送时解析出的、属于 Marvis 应用的 open_id；点击时用它核对点击人 |
| `target_name` / `target_avatar_url` | 群名或人名、头像，列表展示用 |
| `role` | `member` 或 `admin` |
| `max_uses` / `use_count` | 群卡片人数上限（空表示不限）；个人卡片固定为 1 |
| `expires_at` / `revoked_at` | 过期时间、撤销时间 |
| `note` | 附言，最多 200 字 |
| `lark_message_id` | 卡片消息 ID，撤销、更新人数时用 |
| `sent_by_user_id` / `sent_by_agent_id` | 授权发送的人；智能体代发时同时记智能体 |
| `created_at` | 创建时间 |

状态不落库，按字段推导：`revoked`（有撤销时间）、`expired`（已过期）、`completed`（达到上限）、`active`（其余）。

`lark_invite_join`：谁通过哪张卡片加入。字段 `invite_id`、`user_id`、`lark_open_id`、`joined_at`，(`invite_id`, `user_id`) 唯一。

席位容量只在连了 Multica Cloud 时启用，Marvis 自托管不会打开。席位容量开启时飞书邀请整体不可用（返回 `lark_not_configured`），不为它新增席位意图类型。

所有业务词表（状态、目标类型、ID 类型、错误码）定义为具名常量。

### 3. 发卡片

入口是 `POST /api/workspaces/{id}/lark-invites`，界面和 CLI 共用。界面可以一次选多个群或多个人；CLI 一次只传一个接收方。每个接收方独立处理，一个失败不影响其他：

1. 校验权限（第 8 节）和参数。
2. 解析接收方：
   - 群：调用群信息接口拿群名、人数；机器人不在群里返回 `bot_not_in_chat`。
   - 个人：CLI 传的是 open_id，直接用它取姓名、头像；界面传的是邮箱，先换成 Marvis 应用的 open_id。查不到返回 `user_not_found`，不在可用范围返回 `user_not_in_app_scope`，open_id 不属于本应用返回 `open_id_cross_app`。
3. 写 `lark_invite`，再发卡片：群用 `receive_id_type=chat_id`，个人用解析出的 open_id。发送失败时删除这条记录，返回失败原因。
4. 记下 `lark_message_id`。

飞书接口不支持批量发卡片，每个接收方各调一次；在代码注释里写明原因。多个接收方用有上限的并发发出，不在循环里串行调用。

卡片内容（与 32 号画板一致）：标题“工作区邀请”；正文“{发送人} 邀请你加入工作区 {工作区名}”，智能体代发时为“{智能体} 代 {发送人} 邀请你加入……”；附言；角色、有效期至；主按钮“加入工作区”（回传 `invite_id`）；次按钮“下载 Marvis”（链接）；群卡片底部显示已加入人数和头像。群卡片要开启共享卡片更新（`update_multi`），人数变化时所有人看到的都更新。

### 4. 点击加入

飞书通过长连接把 `card.action.trigger` 推给服务端。服务端必须在 3 秒内回应，所以只做必要的判断，卡片人数的更新放在回应之后异步做：

1. 按回传值找到 `lark_invite`，检查状态：撤销或过期回“邀请已失效”，并把卡片改成失效状态；达到上限回“邀请人数已满”。找不到这条邀请时（比如点击被推给了另一个部署）只回“邀请已失效”，不改卡片。
2. 校验点击人：组织必须在 `MARVIS_LARK_LOGIN_TENANT_KEYS` 允许的范围内（未配置时不限），否则回“此邀请仅限本组织成员”；个人卡片的点击人 open_id 必须等于 `target_open_id`。
3. 用通讯录接口拿点击人的邮箱、姓名、头像。邮箱取法和飞书登录一致：先 `email`，没有再用 `enterprise_email`。都没有时回“飞书账号没有邮箱，无法加入”。
4. 按邮箱找到或新建 Marvis 账号，新账号带上飞书姓名和头像。新建账号受现有注册限制约束（`ALLOW_SIGNUP` 等），被拒时回对应提示。
5. 已是成员回“你已在 {工作区} 中”。否则加为成员，走和分享链接加入相同的逻辑：席位检查、成员写入、`member_added` 事件、清理同邮箱的待接受邀请、通知守护进程。实现时把 `JoinByShareLink` 里这段抽成公共函数，两处共用。席位已满回“{工作区} 成员已满，请联系管理员”。
6. `use_count` 加一并写 `lark_invite_join`，两者和成员写入在同一个事务里；`use_count` 用条件更新防止并发超额。
7. 回应提示“已加入 {工作区}，打开 Marvis 用飞书登录即可”。个人卡片在回应里直接把卡片换成“已加入”状态；群卡片在回应之后异步更新人数和头像。

提示文案见 32 号画板第 ⑤ 块，界面文字遵守“中性、简短、陈述式”。

### 5. 撤销与过期

- 撤销：`DELETE /api/workspaces/{id}/lark-invites/{inviteId}` 写 `revoked_at`，再更新卡片为“邀请已失效”、按钮置灰。更新卡片失败不回滚撤销，记日志。
- 过期：不跑定时任务。过期后有人点击，按第 4 节第 1 步处理并顺手更新卡片；列表里状态按字段推导，立即显示“已过期”。

### 6. 长连接

现有的 `server/internal/integrations/lark` 已经实现了飞书长连接（`WSLongConnConnector`、`HTTPConnectionTokenFetcher`），但只处理消息事件，收到其他类型会丢弃。需要：

- 用登录应用的凭据起一条长连接。登录应用不是 `lark_installation` 里的一行，在内存里构造 `Installation` 和凭据即可，不走现有的租约和数据库。
- 在帧解码里识别卡片回调帧，交给第 4 节的处理函数，并按长连接协议把回应写回同一条连接。
- 服务端多副本时每个副本各起一条连接，飞书只会把一次点击推给其中一条。

这一块是最大的不确定点，开工第一步先用一张测试卡片跑通（见“风险与先做的实测”）。

### 7. 接口

都在工作区路由下，除特别说明外要求管理员或所有者：

| 方法与路径 | 用途 |
|---|---|
| `POST /api/workspaces/{id}/lark-invites` | 发卡片，入参 `chat_ids[]`、`user_open_ids[]`、`user_emails[]`、`role`、`expires_in`（小时）、`max_uses`、`note`、`idempotency_key`；返回每个接收方的结果 |
| `GET /api/workspaces/{id}/lark-invites?status=` | 列表，默认只返回 `active` |
| `GET /api/workspaces/{id}/lark-invites/{inviteId}` | 详情和已加入的人 |
| `DELETE /api/workspaces/{id}/lark-invites/{inviteId}` | 撤销 |
| `GET /api/workspaces/{id}/lark/chats` | 机器人所在的群，界面选择用，CLI 不暴露 |
| `GET /api/workspaces/{id}/lark/users/lookup?email=` | 按邮箱查飞书资料，界面预览用 |
| `GET /api/lark/status` | 飞书机器人是否可用，成员页决定显示列表还是未配置提示；所有成员可读 |

### 8. 权限

- 所有飞书邀请接口（发送、列表、详情、撤销、列群、查人）都放在现有的管理员路由组里，由 `RequireWorkspaceRoleFromURL` 校验请求人是管理员或所有者。智能体请求时，这里校验的是智能体所属的账号（运行时所有者）。
- 智能体在任务里调用（请求带任务身份）时，再加一道校验：任务的 `originator_user_id` 也必须是该工作区的管理员或所有者；为空时拒绝。两道都过才放行，失败返回 `permission_denied`。这道校验对发送、列表、详情、撤销都生效。

### 9. CLI

```
marvis workspace lark-invite send   [workspace-id|slug|prefix] (--chat-id oc_xxx | --user-id ou_xxx) [flags]
marvis workspace lark-invite list   [workspace-id|slug|prefix] [--status active|completed|expired|revoked|all]
marvis workspace lark-invite get    <invite-id>
marvis workspace lark-invite revoke <invite-id>...
```

接收方参数照搬飞书 CLI `lark-cli im +messages-send` 的写法，智能体从飞书 CLI 拿到的 ID 原样传进来：

| 参数 | 取值 | 默认 | 说明 |
|---|---|---|---|
| `--chat-id` | 群 ID（`oc_xxx`） | — | 发到群里；和 `--user-id` 二选一，必填其一 |
| `--user-id` | 用户 open_id（`ou_xxx`） | — | 发给个人；和 `--chat-id` 二选一，必填其一 |
| `--role` | `member`、`admin` | `member` | 加入后的角色 |
| `--expires-in` | `1h` 到 `30d` | `7d` | 有效期 |
| `--max-uses` | 整数，0 表示不限 | `0` | 群卡片人数上限；发给个人时忽略 |
| `--note` | 最多 200 字 | 空 | 附言 |
| `--idempotency-key` | 最多 50 个字符 | 空 | 防止重复发送，同飞书 CLI；透传给飞书发消息接口的 `uuid` |
| `--output` | `table`、`json` | `table` | 输出格式，沿用 Marvis CLI 的约定 |

- 一次一个接收方，和飞书 CLI 一样；要发多个就调多次。界面上的多选走同一个接口的数组入参。
- 智能体查 ID：群用 `lark-cli im +chat-search --query <群名>`，人用 `lark-cli contact +search-user`（需要 `--as user`）。
- open_id 按飞书应用区分。飞书 CLI 配置的应用必须和 Marvis 飞书登录用的是同一个（`MARVIS_LARK_LOGIN_APP_ID`），否则查出来的 open_id 发不了，返回 `open_id_cross_app`。帮助文本和错误提示里都写明这一点。现在这台电脑上两者是同一个应用。

输出与报错用英文。表格把可能含中文的 TARGET 放在最后一列，避免中文字宽把后面的列挤歪。发送失败时打印原因，退出码为 1。各命令的输出样例见 34 号画板。

错误码（JSON 输出的 `error.code`，界面也用同一套）：

| code | 什么时候 |
|---|---|
| `lark_not_configured` | 服务端没配登录应用，或没开机器人 |
| `permission_denied` | 请求人或任务发起人不是管理员或所有者 |
| `bot_not_in_chat` | Marvis 机器人不在这个群 |
| `user_not_found` | open_id 或邮箱在飞书里查不到 |
| `user_not_in_app_scope` | 对方不在应用可用范围 |
| `open_id_cross_app` | open_id 属于别的飞书应用，飞书 CLI 要改用 Marvis 的应用 |
| `invalid_target` | ID 格式不对，或 `--chat-id` / `--user-id` 都没传、都传了 |

### 10. 前端（设计稿 30、31、33 号画板）

- 成员页新增“飞书邀请”标签页：列表显示接收方、角色、已加入的人、有效期、发送人和状态，可撤销；空状态；未配置状态。列表请求 `status=all`，有效的排在前面。没有网页端时也显示（和分享链接不同，它不依赖浏览器打开链接）。
- 发送弹窗：群聊（从机器人所在的群里多选，可搜索）和个人（输入邮箱，回车添加，显示飞书姓名和部门，查不到的标红）两个标签；角色、有效期、人数上限（仅群聊）、附言；右侧实时预览卡片。
- 新成员第一次打开通过飞书邀请加入的工作区时，弹一次提示“已加入 {工作区}”。
- 收到 `member_added` 事件后刷新列表里的已加入人数。
- 头像遵循 24 号规范，见第 11 节。

### 11. 头像

- 显示：成员圆形、智能体和小队圆角方形；没有图片时浅灰底黑字；只有 Marvis 标志是黑色；有图片直接显示图片。
- 同步时机只有两个：飞书登录时（改 `issueOAuthLogin` 里飞书登录的分支），和点卡片新建账号时。不做后台刷新。
- 覆盖规则：用户当前头像为空，或者是第三方资料链接时，用飞书头像覆盖。用户在 Marvis 里上传的图片（`ownedStorageKey` 能识别的本服务存储文件）和表情头像保持不变。
- 现有的 Google 登录不受影响，仍然只在头像为空时写入。
- 如果风险第 5 条实测发现飞书头像链接会过期、需要下载进本服务存储，下载后的文件会被当成“用户上传”，就需要另加标记区分，到时候再改。

## 风险与先做的实测

开工第一步做一个最小验证，跑通之前不铺开实现：

1. 登录应用通过长连接收到 `card.action.trigger`，并能在 3 秒内回应提示、替换卡片。
2. 群卡片开启 `update_multi` 后，用消息 ID 更新卡片，群里所有人看到的都变。
3. 飞书 CLI 查到的群 ID 能被 Marvis 应用直接使用（预期可以，群 ID 不区分应用）。
4. 用 `contact:user.email:readonly` 能拿到点击人的邮箱。
5. 飞书头像链接长期可访问；如果会过期，改为下载后存进本服务存储。

其他已知限制：

- 转发出去的卡片按钮会被飞书禁用；要邀请别的群，先把 Marvis 机器人拉进那个群。
- 点击加入不要求同事电脑能连上服务器（长连接由服务端主动连飞书），但之后使用 Marvis 仍然要连得上服务器。

## 测试

- 服务端：
  - 发卡片：群、个人、混合；部分失败；各错误码；幂等键重复发送；智能体代发的权限判断（发起人是管理员 / 普通成员 / 为空）。
  - 点击：正常加入；重复点击；已是成员；过期；撤销；达到上限；并发点击不超额；个人卡片被别人点击；组织不在允许范围；席位已满；新建账号带头像。
  - 撤销：卡片更新失败不影响撤销。
  - 头像同步：空头像、第三方链接、上传文件、表情头像四种情况；Google 登录行为不变。
  - 开关关闭时不起长连接、接口返回 `lark_not_configured`；找不到邀请时不改卡片。
  - 智能体代发：运行时所有者和发起人都是管理员才放行，任一不是就拒绝。

- 前端：成员页三种状态、发送弹窗两个标签、首次进入提示只出现一次。
